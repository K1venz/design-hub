## A-1 mysql 3306 收 bind（ISSUE-0036）

**改**：server `/opt/docker/mysql/compose.yml`（非 repo，server-only）：
```
-      - "0.0.0.0:3306:3306"
+      - "127.0.0.1:3306:3306"
```
（文件里已有注释建议此改）→ `cd /opt/docker/mysql && docker compose up -d`（recreate mysql）。
**风险/停机**：⚠️ recreate mysql = **DB 短暂断 ~5-15s**，api/qa 容器丢连接后自动重连（healthcheck 兜）。**建议低峰执行 + 执行前 dump 一份**。改后 api↔mysql 走 docker 网络（mysql:3306）不受影响、QA 的 13306 隧道仍可（隧道连的是 server localhost:3306=新 bind 命中）。
**回滚**：改回 `0.0.0.0` + recreate。
**校验**：改后本机外网 `nc 203.0.113.10 3306` 应仍 filtered（本就被安全组挡）、server 内 `ss` 看 3306 bind 变 127.0.0.1。**外加**：用户在火山安全组**删 3306 入站规则**（纵深，需用户操作）。

## A-2 nginx：收口 /docs·/metrics + 安全头 + 限流（含 dev #585 nginx 层）

**改**：`image-ops/deploy/nginx/conf.d/design-hub.conf`：
1. **顶部加限流 zone**（http 块——注意：现 conf 只有 server 块，limit_req_zone 须在 http 级，放 `image-ops/deploy/nginx/conf.d/` 另起 `00-ratelimit.conf` 或确认 nginx.conf include 顺序）：
   ```
   limit_req_zone $binary_remote_addr zone=reg:10m  rate=5r/m;    # 注册
   limit_req_zone $binary_remote_addr zone=login:10m rate=15r/m;  # 登录
   limit_req_zone $binary_remote_addr zone=gen:10m  rate=10r/m;   # 出图(兜底,app层per-user为主)
   ```
2. **server 块加安全响应头 + server_tokens off**：
   ```
   server_tokens off;
   add_header Strict-Transport-Security "max-age=31536000" always;
   add_header X-Frame-Options          "DENY" always;
   add_header X-Content-Type-Options   "nosniff" always;
   add_header Referrer-Policy          "strict-origin-when-cross-origin" always;
   # CSP 上线前细调(SPA 内联/字体源)，先 Report-Only 观察
   ```
3. **/docs·/redoc·/openapi.json·/metrics 关公网**（删/改这 4 个 location 为内网限制）：
   ```
   location = /metrics      { allow 172.16.0.0/12; deny all; proxy_pass http://design_hub_api; }
   location = /openapi.json { return 404; }   # 上线后契约不公开
   location /docs           { return 404; }
   location /redoc          { return 404; }
   ```
4. **限流挂到 /api 子路径**（在 location /api/ 内或加精确 location）：
   ```
   location = /api/auth/register { limit_req zone=reg burst=3 nodelay;  ... proxy_pass ... }
   location = /api/auth/login    { limit_req zone=login burst=5 nodelay; ... }
   ```
   （需复制 /api/ 的 proxy 头；或用 map+单 location，apply 时给完整块）
**风险/停机**：nginx reload 零停机（`nginx -t` 校验通过再 reload）。限流误伤=NAT 共享 IP（toC 早期可接受、dev app 层 per-user 为主防线）。
**回滚**：`git revert` conf + `docker exec design-hub-nginx nginx -s reload`。

## A-3 SSH 加固（🔒 防锁死，分步、留兜底 session）

**改**：server `/etc/ssh/sshd_config.d/99-hardening.conf`（新建、覆盖 50-cloud-init 的 yes）：
```
PermitRootLogin prohibit-password
PasswordAuthentication no
PubkeyAuthentication yes
```
+ 装 fail2ban（`apt install fail2ban`，默认 sshd jail）。
**🔒 防锁死铁律（apply 时严格按序）**：
1. apply 前**先开一个独立 SSH session 挂着别断**（兜底逃生）；
2. 确认 `~/.ssh/dh_deploy_ed25519` 密钥登录**实测可用**（现就是密钥登录的，已验）；
3. 写 99-hardening.conf → `sshd -t` 语法校验 → `systemctl reload sshd`（**reload 不断现有连接**）；
4. **用新连接验证**密钥登录仍通、密码登录已拒——通过了才关那个兜底 session；不通立即 `rm 99-hardening.conf + reload` 回滚。
**回滚**：删 99-hardening.conf + reload sshd。
**风险**：操作失误=自锁（故有兜底 session + 火山控制台 VNC 终极逃生）。
