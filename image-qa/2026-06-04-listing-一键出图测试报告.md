## 三、缺陷

### ① [主] 边界校验未 fail-fast：n/ratio/未知下拉/空prompt 返 200+job_id 而非 4xx（→ ISSUE-0024，P2）
- spec §4.1(line 82)「校验在边界完成（fail-fast）：images 数量、n 范围、ratio 合法、modifiers 可解析」、§7(line 159-160)「边界校验失败（图数/n/ratio/modifiers/未知下拉值）→ 4xx，不降级」。
- 实测：路由 `listing.py` 只同步校验「图数 1..3」与「modifiers 是 JSON 对象」；**n 范围、ratio 合法、未知下拉值、空 prompt 都在 `ListingGenerationService.generate()`（异步命令内）才校验** → HTTP 先返回 200+job_id，错误经 SSE `task_failed` 暴露。
- 影响：调用方拿到 job_id 以为成功、需订阅 SSE 才知失败；与"边界 fail-fast 4xx"契约不符。错误未静默（仍 task_failed），故 P2 非 P0/P1。

### ② [次] 边界 4xx 错误码不符 spec：DomainError→409 / 0图→422，spec 要 400（→ ISSUE-0024，P3）
- 图数越界、非对象 modifiers 走 `DomainError`→边界映射 **409**；0 图 FastAPI **422**。spec/ISSUE-0023 均写 **400**。
- 建议：边界输入校验错误统一 400（与 ValueError 一致），DomainError(409) 留给真实领域冲突。

### ③ [轻] sizing 接受 4:3（超出确认集）（→ ISSUE-0024 备注，P3）
- `_RATIO_TO_SIZE` 含 `4:3→1536×1024`，超出 ISSUE-0021 确认的 1:1/3:4/9:16/16:9。无害但属未确认取值，建议与 PM 对齐保留或删除。
