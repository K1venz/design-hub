# QA 用例骨架 · listing 二次编辑（基于结果迭代再生成）

> 状态：**骨架**（PRD 未出，coordinator #399 派 QA 提前备）。
> 用途：① 作为 QA 验收基线 ② 反哺 PM 的 PRD——下方「PRD 开放问题」是要 PM 拍的契约点。
> PRD 落定后，本骨架细化为可跑脚本（参考既有 `listing_*_regression.py` / `listing_real_boundary.py`）。

## 0. 功能理解（待 PRD 校正）

二次编辑 = 用户拿**自己某次 listing 的生成结果图** + **新/改提示词** → 再过一次 `/images/edits` → 出新图，可迭代多轮。
后端已有 `/images/edits` 图生图能力（ISSUE-0007），缺的是 listing 的「基于结果再编辑」编排流（async job + SSE + 持久化 + 计费）。

## 1. 验收维度（按优先级，每条都要独立验）

| # | 维度 | 严重度 | 验收点 |
|---|---|---|---|
| D1 | **迭代链 owner 隔离** | P0 安全 | 只能基于**自己**的结果再编辑。别人的 / 不存在 / 畸形 source id → **404**（沿用 ISSUE-0032 anti-enumeration：不泄漏存在性）。 |
| D2 | **保真不崩** | P0 功能 | 二次编辑后产品本体 + 包装文字 100% 保真；**多轮迭代累积失真受控**（每轮都过一次 edits，失真会不会叠加是核心风险）。 |
| D3 | **二次 prompt 生效** | P1 功能 | 新诉求真体现（例「背景换纯白」→ 背景白）**且不破坏 D2 保真**。 |
| D4 | **成本按次计** | P1 成本 | 每次二次编辑 = 一次真实 edits 调用 → 各计一次费，cost 正确累加，**不漏计、不重复计**。 |
| D5 | **源选择正确** | P1 功能 | 二次编辑用的源 = 用户**选中的那张结果图**，不是原始上传图、不是同 job 别的结果。 |
| D6 | **async + SSE 一致** | P1 一致 | 二次编辑也是 async job + SSE 事件流（task_started→model_called→image_generated→task_completed），`?access_token=` 鉴权同 ISSUE-0011。 |
| D7 | **失败 fail-fast** | P2 健壮 | provider 错 / key 失效 → job status=失败、**不静默吞**、不回落假图；计费可追溯（失败是否扣费按 PRD，但必须可查）。 |
| D8 | **边界** | P2 边界 | 迭代深度上限、一张结果能否分叉多次、ratio/category/modifiers 继承 or 可改——见开放问题。 |

## 5. 编辑模式 delta / full 对 QA 断言的影响（prompt #404、coordinator #406 确认要拍交互模型）

二次编辑交互模型有两种，**QA 的保真口径随模式不同、锁断言时必须按模式分支**：

| 模式 | 用户给的 | QA 保真断言 |
|---|---|---|
| **delta**（改动指令，prompt 建议默认） | 增量微调（换背景 / 散落花生再多点 / 调暖光） | **最严**：产品本体 + 品牌文字 + **上一版构图基底**都不变，**只有 delta 那部分变**；delta 以外动了任何东西 = fail。多轮 delta 累积失真 = TC-05 重点。 |
| **full**（重写需求，可选） | 全新场景需求 | 产品本体 + 品牌文字仍锁死，但构图 / 背景允许整体变（以上一版结果为保真锚）。构图变是**预期**、不判 fail。 |

→ 同一张图同一句 prompt，在 delta 模式动了构图基底 = fail，在 full 模式 = pass。**交互模型（delta / full / 都要）由 coordinator 从用户拿**，定了我据此分裂 D2/D3 的断言。
