# QA 用例骨架 · listing 二次编辑（基于结果迭代再生成）

> 状态：**骨架**（PRD 未出，coordinator #399 派 QA 提前备）。
> 用途：① 作为 QA 验收基线 ② 反哺 PM 的 PRD——下方「PRD 开放问题」是要 PM 拍的契约点。
> PRD 落定后，本骨架细化为可跑脚本（参考既有 `listing_*_regression.py` / `listing_real_boundary.py`）。

## 0. 功能理解（待 PRD 校正）

二次编辑 = 用户拿**自己某次 listing 的生成结果图** + **新/改提示词** → 再过一次 `/images/edits` → 出新图，可迭代多轮。
后端已有 `/images/edits` 图生图能力（ISSUE-0007），缺的是 listing 的「基于结果再编辑」编排流（async job + SSE + 持久化 + 计费）。

## 1. 验收维度（按优先级，每条都要独立验）

| # | 维度 | 严重度 | 验收点 |
|---|---|---|---|
| D1 | **迭代链 owner 隔离** | P0 安全 | 只能基于**自己**的结果再编辑。别人的 / 不存在 / 畸形 source id → **404**（沿用 ISSUE-0032 anti-enumeration：不泄漏存在性）。 |
| D2 | **保真不崩** | P0 功能 | 二次编辑后产品本体 + 包装文字 100% 保真；**多轮迭代累积失真受控**（每轮都过一次 edits，失真会不会叠加是核心风险）。 |
| D3 | **二次 prompt 生效** | P1 功能 | 新诉求真体现（例「背景换纯白」→ 背景白）**且不破坏 D2 保真**。 |
| D4 | **成本按次计** | P1 成本 | 每次二次编辑 = 一次真实 edits 调用 → 各计一次费，cost 正确累加，**不漏计、不重复计**。 |
| D5 | **源选择正确** | P1 功能 | 二次编辑用的源 = 用户**选中的那张结果图**，不是原始上传图、不是同 job 别的结果。 |
| D6 | **async + SSE 一致** | P1 一致 | 二次编辑也是 async job + SSE 事件流（task_started→model_called→image_generated→task_completed），`?access_token=` 鉴权同 ISSUE-0011。 |
| D7 | **失败 fail-fast** | P2 健壮 | provider 错 / key 失效 → job status=失败、**不静默吞**、不回落假图；计费可追溯（失败是否扣费按 PRD，但必须可查）。 |
| D8 | **边界** | P2 边界 | 迭代深度上限、一张结果能否分叉多次、ratio/category/modifiers 继承 or 可改——见开放问题。 |

## 2. 用例骨架（PRD 后填具体断言/源数据）

| 用例 | 维度 | given → when → then |
|---|---|---|
| TC-01 happy path | D2 D5 D6 | 自己有一张结果图 → 选它 + 新 prompt 二次编辑 → 真出图、SSE 事件全、产品保真、源就是那张 |
| TC-02 越权·他人结果 | D1 | A 的结果 id，B 来二次编辑 → **404** |
| TC-03 越权·不存在/畸形 | D1 | source id = 不存在 / 畸形串 → **404**（与 TC-02 返回不可区分） |

| TC-05 多轮迭代累积失真 | D2 | 同图连做 3 轮二次编辑 → 逐轮视觉核：产品本体/文字不漂、不累积糊 |
| TC-06 计费 | D4 | 二次编辑 N 次 → 单次各扣一份、链路累计 = N×单价（核 total_cost 口径） |

| TC-08 失败 fail-fast | D7 | 注入 provider 失败（key 失效）→ job 失败、不出假图、计费可追溯 |

| TC-10 参数继承/可改 | D8 | 二次编辑时改 ratio/category/modifiers → 按 PRD（继承父 or 允许覆盖） |

## 3. PRD 开放问题（喂给 @PM 拍契约，QA 的断言依赖这些）

- **Q1 入口数据契约**：二次编辑请求带什么？`parent_job_id + image_index`？还是独立的 `result_image_id`？（决定 D1/D5 怎么测）
- **Q2 源图来源**：把结果图（TOS url）回灌 `/images/edits`，还是用 TOS 里那张对象？签名 url 过期了怎么办（呼应 ISSUE-0034）？
- **Q3 迭代深度 / 分叉**：有上限吗？一张结果能被多次二次编辑分叉吗？
- **Q4 参数继承**：ratio / category / modifiers 在二次编辑能改吗，还是继承父 job？
- **Q5 成本展示**：给用户看单次还是整条迭代链累计？（决定 D4 断言口径）
- **Q6 产物落桶 + job 关系**：新图落 generate 桶？二次编辑是新 job（带 parent 指针）还是挂同 job？（决定历史怎么测）
- **Q7 历史展示**：迭代链在历史/列表里如何呈现父子关系？

## 4. 复用既有资产

- 越权 404 模型：ISSUE-0032 / `listing_real_boundary.py` 的 C1 ownership case 可直接扩到二次编辑 source。
- SSE access_token：ISSUE-0011 既有断言。
- 真出图成本闸：沿用 n=1 精确控成本 + 两阶段成本 gate（`listing_acceptance_batch.py`）。
- 收窄一致：若二次编辑也走 modifiers，复用 `listing_narrow_regression.py` 的收窄断言。
