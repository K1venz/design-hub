## 一、Bug 清单（按严重度降序，Bug 1 最严重）

### Bug 1 [P1] 移动端公开首页 Hero 崩溃，落地页在手机上不可用
- **现象**：390px 手机档，左侧导航 `SideNav` 固定 **212px 宽、无汉堡/抽屉收起**，恒占屏 >54%，正文被挤到 ~142px：Hero 标题「和我聊聊，你想要什么设计？」被压成 **1 字/行竖排**；Hero 输入框压到几乎不可读；「添加图片 / 发送」挤叠；右上「内测免费」徽标 + 头像被裁到屏外。
- **复现步骤**：1. `browser_resize` 到 390×844；2. 打开 `/`；3. 观察 Hero 区。
- **截图**：`image-qa/audit-shots-2026-07-06/home-390px-viewport.png`（1 字/行铁证）、`home-390px.png`
- **根因猜测**：`SideNav` 无响应式断点（缺 `md:` 把导航收为抽屉/汉堡）；`AppShell` 用固定宽侧栏 + flex 内容，窄屏不堆叠。**768 / 1440 两档 0 溢出、完全正常**——问题仅在手机档。
- **影响面**：公开首页是对外获客落地页（PRD §7.G），toC 场景**手机打开/分享是主流量入口**，当前观感等于「打不开」。故定 P1（而非工作台的 P2）。

### Bug 2 [P2] 「记住我」复选框是摆设——勾/不勾 token 都永久落 localStorage
- **现象**：登录页勾选「记住我」与**取消勾选**两种情况，token 均写入 `localStorage['design-hub-auth']`，`sessionStorage` 始终为空。即取消「记住我」后关浏览器再开，登录态仍在——在**共享/公用电脑**上违反用户对「不记住我」的安全预期。
- **复现步骤**：1. `/login` 取消勾「记住我」；2. 填 admin 账密登录；3. `localStorage.getItem('design-hub-auth')` → 有 token；`sessionStorage` → 空。勾选时同样落 localStorage。
- **截图**：（取证为 storage 读值，见正文数据）勾选态 / 取消态两次读取均 `localStorage` 命中、`sessionStorage` 空。
- **根因猜测**：auth store（zustand persist）**硬编码 `localStorage`**，未按「记住我」布尔切换 `localStorage`↔`sessionStorage`。
- **备注**：此项**已知、正在修复中**（另一前端 agent 在主工作树处理）；本条是对提交 `f4e1104` 的**现状取证**，供修复后回归对照，**非要求本 agent 修**。

### Bug 3 [P2] 套图工作台 /set 移动端横向溢出（body 可侧拖）
- **现象**：390px 档，`/set` 页 `scrollWidth ≈ 608` vs 视口 `375`，**横向溢出 ~233px**，body 可左右拖动，双栏工作台未做移动端堆叠。
- **复现步骤**：1. resize 390；2. 打开 `/set`；3. 量 `documentElement.scrollWidth > clientWidth`。
- **截图**：`image-qa/audit-shots-2026-07-06/set-390px.png`
- **根因猜测**：左配置栏 + 右结果栏最小宽 ~608px，缺窄屏上下堆叠断点。**768 / 1440 正常**。
- **影响面**：工作台移动端使用较少（美工用桌面），故次于 Bug 1。

### Bug 4 [P3] /chat 发送后用户消息明文泄漏进 URL（?q=…）
- **现象**：在 `/chat` 输入框发送消息后，地址栏变为 `/chat?q=<整条消息的 URL 编码>`。用户对话内容进入**浏览器历史 / 地址栏 / 潜在 referer**，toC 隐私不佳；且刷新 URL 有重复触发风险。
- **复现步骤**：1. `/chat` 输入任意文本；2. 点发送；3. 看地址栏出现 `?q=…`。
- **根因猜测**：发送处用 query 参数承载草稿/消息（可能是「首页输入框跳转 chat」复用的 draft 透传逻辑），未在进入会话后清理。
- **建议**：消息用组件 state / POST body 承载，进会话后 `replaceState` 清掉 `?q=`。

### Bug 5 [P3] /chat 澄清轮把内部字段名 `upload_ids` 暴露给终端用户
- **现象**：未上传图就描述需求时，助手回复：「出图参数还差点信息、暂时没法出图（**upload_ids 数量需为 1..3，实际 0**）。」把后端字段名 `upload_ids` 原样吐给 C 端用户。
- **复现步骤**：1. `/chat` 不传图；2. 发「白底1张、场景2张、卖点2张，比例1:1」；3. 看回复括号内文案。
- **根因猜测**：orchestrator 校验失败信息直接回传，未做面向用户的话术包装。
- **建议**：改为「请先上传 1–3 张产品图，我再帮你安排」。

### Bug 6 [P3·未稳定复现] 上传图片过程偶发被踢回 /login
- **现象**：在 `/chat` 走「添加图片 → 选文件」流程时，出现过 2 次页面瞬时跳到 `/login`（随后又回到已登录首页，token 未真正丢失）。未能稳定复现，疑似上传/鉴权时序竞态或 401 瞬态触发路由守卫。
- **复现步骤**：不稳定；`/chat` 反复触发文件选择 + 上传时偶发。
- **根因猜测**：上传接口偶发 401（token 刷新/并发）→ 路由守卫抢跳 `/login`。
- **建议**：观察项，建议在上传链路加 401 重试/静默续期，避免误跳登录。

## 二、UI/UX 优化清单

### 高价值
### 优化 1 移动端响应式一揽子（修 Bug 1 + Bug 3）
- **现状**：`SideNav` 固定 212px 无断点；首页 Hero / 6 快捷卡 / 工具区 banner / 成果区、`/set` 双栏在手机档全不堆叠。
- **建议**：`SideNav` 加 `md` 断点——<768 收为**汉堡抽屉**（点击滑出、遮罩关闭）；首页 Hero/6 卡/工具区窄屏**单列堆叠**；`/set` 配置栏与结果栏**上下堆叠**。一次解决落地页手机观感 + 工作台移动可用。

### 优化 2 「记住我」落地真语义（配合 Bug 2 修复）
- **现状**：勾/不勾都 `localStorage` 永久存。
- **建议**：勾 →`localStorage`（持久）；不勾 →`sessionStorage`（关页即失效）。前端 persist store 按布尔切 storage。

### 优化 3 chat 澄清/错误文案人话化（配合 Bug 5）
- **现状**：「upload_ids 数量需为 1..3，实际 0」这类含字段名的机器话术直吐用户。
- **建议**：统一过一层用户文案映射，去掉所有内部字段名/技术黑话。

### 顺手可做
### 优化 4 chat 消息不进 URL（配合 Bug 4）
- **现状**：发送后 `/chat?q=<消息>`。
- **建议**：改 state/POST 承载，进会话后清 query。

### 优化 5 「忘记密码」补联系方式
- **现状**：入口为 disabled 态、tooltip「找回密码即将上线」；弹窗联系方式常量（`ADMIN_CONTACT` 类）为空。
- **建议**：待用户给微信/邮箱补一行真实联系方式，先给「联系管理员找回」兜底而非纯灰置。

### 优化 6 /history 移动端卡片 + 下载一致性
- **现状**：历史列表卡片在桌面正常；「下载全部」与单张「下载」按钮文案/图标风格可统一；移动端卡片布局未验（Bug 1 修复时一并覆盖）。
- **建议**：随移动端一揽子把历史卡片做窄屏单列；「下载」交互统一。
