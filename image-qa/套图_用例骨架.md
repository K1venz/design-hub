## 0. 现行代码基线（QA 读码锚点，断言以此为准）

`listing_service.py` 现行成本/失败先例（`generate()`，listing_service.py:46-90）：
- `estimate = unit_cost × n` → `guard.precheck_and_reserve`（全额预扣）
- N 张**并发单图**（`asyncio.gather(return_exceptions=True)`，部分失败容错 = I/O 域）
- **全失败** → `guard.rollback(estimate)` + raise（job 失败）
- **部分/全成功** → `total = Σ成功张 cost` → `guard.reconcile(reserved=estimate, actual=total)` = **只计成功张**
- ⚠️ **契约红旗**：现行 `_MAX_N = 7`、`_MAX_IMAGES = 3`（listing_service.py:17-18）。套图总数上限若 >7，**必改 _MAX_N 或走独立编排上限**——dev 方案须明列，QA 边界用例跟 PM 终值锁。

## 3. PRD / 设计三方对 开放问题（QA 断言依赖）

- **S1 图型枚举与 MVP 范围**：MVP 是 4 型全做还是 3 型（「其他/智能补位」型在「智能匹配后置 backlog」前提下，MVP 语义是什么？纯占位还是砍掉？）——决定 T1/T2 的枚举断言。
- **S2 总数上下限 + 默认配比**：PM 提案保守值（竞品 7~20 / 默认 1/2/2/2；toC 兜成本）。⚠️ 联动 `_MAX_N=7` 契约红旗（§0）。
- **S3 入参 shape**：`{白底:1, 场景:2, ...}` 计数字典还是列表？图型枚举名（中文/英文 key）？——决定脚本请求体。
- **S4 卖点图与 P0.5 关系**：MVP 套图的「卖点图」带不带图上文案？（P0.5 带文案卖点图是独立需求——若 MVP 不带，视觉核口径=细节特写不强求文案）。
- **S5 图型卡组装序**：prompt 的「保真块 × 图型卡 × 用户文本 × modifier」拼接顺序与每型一卡的单一事实源（.md 卡 ↔ 代码副本逐字核对机制是否沿用现行品类卡铁律）——决定 QA 逐字核对清单。
- **S6 ratio 是否全套统一**：一套一 ratio 还是每型可异 ratio？——决定 TT-01/14 断言。
- **S7 DB schema**：listing_image 加图型列等迁移点（dev 方案列出 → **用户签字后才动**，QA 届时加迁移生效断言）。

## 4. 成本闸（QA 自律，沿用两阶段 gate）

- 边界/契约用例（T2/T6/T7/T8 大部分）用 GHOST upload id 或脏输入：**零出图、零成本**（compose/校验层 fail-fast 在出图前）。
- 真出图仅 happy path + 保真矩阵 + 部分失败：qa env、最小配比（如 1/1/1/1=4 张 ≈ $0.20/轮），跑前报预算。
- prod smoke 仅部署后 1 套最小配比 + 只读探针，沿用「默认配置真出图」铁律（bug B 教训：UI 默认值必真跑）。
