### #0 加密与泄漏面 — PASS

**验证项：**
1. `GET /auth/pubkey` 返回 JSON `{"public_key":"-----BEGIN PUBLIC KEY-----..."}` — **确认**

   - 非 500，无 stack trace，human-readable。
5. 同上测试对 /auth/register — **确认**，同样返回 400 + 同样 detail 文案。

### #3 双标签页登出同步 — PASS（机制验证）

Playwright MCP 在同一 browser context 内无真实跨标签页 storage 事件，采用机制模拟验证：

1. 登录（localStorage 模式，记住我勾选）后停在 /history
2. 在 page.evaluate 内直接 dispatch `StorageEvent`（key=design-hub-auth, newValue={state:{token:null}}）模拟"另一标签页登出"
3. `MultiTabLogoutWatcher` 监听器触发 → `useAuthStore.getState().clear()` + `navigate('/login')`
4. evaluate 返回时 `window.location.pathname` 已为 `/login` — **确认**

代码审阅确认逻辑完整：
- `App.tsx:MultiTabLogoutWatcher` 监听 storage 事件，nextToken 为 null 且本页有 token → clear + navigate('/login')
- 仅 localStorage 模式生效（sessionStorage 无跨标签页事件），文档设计已说明。

### #4 错误人话化 — PASS

**4a. 429（nginx 非 JSON text/plain body）：**

搭建 429 代理（Python 20 行，:8001）：对 /auth/login 返回 429 + `text/plain "rate limited"`，其余转发 :8000。
前端 Vite 改指 8001。

登录结果：UI 显示 "**尝试太频繁，请稍等 1 分钟再试**" — **PASS**

代码路径：`auth.ts:if (response.status === 429) throw new Error(RATE_LIMIT_ERROR)` 拦截了非 JSON 429，正确转人话。

**4b. 断网/fetch reject：**

`page.route('**/auth/login', route => route.abort('failed'))` 中断登录请求（pubkey 已预热缓存模拟"掉线非冷启动"）。

结果：UI 显示 "**网络异常，请检查连接后重试**" — **PASS**

代码路径：`.catch((): never => { throw new Error(NETWORK_ERROR) })` 捕获 fetch reject，转人话。

**细节注记（不阻碍关单）：** 冷断网场景（pubkey 也未缓存时），pubkey fetch 先 fail，前端抛"安全通道初始化失败，请刷新页面后重试"，而非"网络异常"。此文案仍是人话且可操作，但与 spec 字面不符。该场景（首次访问即断网）极低概率，且报错操作指引正确（刷新）。建议后续 sprint 将 pubkey fetch 失败统一归入"网络异常"文案，当前不视为阻断。
