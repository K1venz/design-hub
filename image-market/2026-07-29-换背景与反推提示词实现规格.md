# 换背景与反推提示词实现规格

> 日期：2026-07-29
>
> 状态：已确认
>
> 设计依据：用户逐节确认
>
> 第三方接口：[APINebula gpt-image-2-1k 分组](https://docs.apinebula.ai/docs/advanced/image/gpt-image-2-1k/)
>
> 实现 owner：开发

## 一、目标

在不重做现有二次编辑、不新建生成基础设施的前提下，增加：

1. 专用换背景能力：
   - 文字描述目标背景。
   - 上传背景参考图。
   - 页面和 Chat 均可调用。
2. 反推提示词能力：
   - 分析上传图或平台生成图。
   - 复用已经接入的 Chat 模型。
   - 输出结构化分析和中英文提示词。
3. Chat 能力入口：
   - 了解平台真实能力。
   - 信息完整时直接执行。
   - 信息不足时只追问缺失项。
   - 需要精细控制时提供带预填信息的页面入口。

首要产品原则：

> 用户表达目标即可，系统负责匹配能力、补齐必要信息并完成操作。只有确实需要复杂控制时，才引导用户进入对应页面，而且必须自动带入已有信息。

## 二、现状与边界

### 2.1 已有能力直接复用

项目已有完整二次编辑，不在本次重新设计：

- 结果图和历史图可进入二次编辑。
- 支持“微调”和“重做”。
- 已有 `POST /listing/edit`。
- 已有任务入队、Worker、SSE、成本、历史、连续编辑和结果存储。
- 有参考图时，Provider 已调用 APINebula `/images/edits`。
- Provider 已支持重复提交多个 `image` 字段。

### 2.2 APINebula 1K 接口事实

| 项目 | 已公开支持情况 |
|---|---|
| 模型 | `gpt-image-2` |
| 生图 | `POST /v1/images/generations` |
| 编辑 | `POST /v1/images/edits` |
| 参考图 | 一张或多张，重复使用 `image` 字段 |
| 返回数量 | `n` 仅支持 1 |
| 尺寸 | 1K 分组，不支持稳定的 2K/4K 输出 |
| 质量 | `low`、`medium`、`high`、`auto` |
| 返回格式 | `url`、`b64_json` |
| 输入保真 | 编辑接口支持 `input_fidelity=high` |
| 蒙版 | 本页未声明支持，不纳入设计 |

`background` 参数控制透明或不透明输出，不等于场景换背景。本功能通过编辑提示词和背景参考图实现，不混用这两个概念。

### 2.3 本期不做

- 不改造 `/listing/edit`。
- 不做蒙版、画笔、局部选区、自由画布。
- 不做对象消除和智能扩图专用工作流。
- 不做背景素材库、模板市场或批量换背景。
- 不做一次返回多张图。
- 不做 2K/4K 换背景。
- 不开放模型、质量、`input_fidelity`、返回格式等内部参数。
- 不新建模型、任务队列、Worker、图片存储或历史系统。
- 不新建向量数据库或 RAG。
- 不新建提示词数据库。
- 不把透明底并入本期。

## 三、总体方案

采用“独立用例、复用底层管线”：

```text
现有二次编辑
POST /listing/edit
        └── 保持不变

专用换背景
POST /listing/background-replace
        └── 现有 Job / Queue / Worker / Provider / History
                └── APINebula /images/edits

反推提示词
POST /image-prompts/reverse
        └── 现有 Chat 模型连接与工具调用

Chat
        ├── 信息完整：直接调用上述能力
        └── 复杂控制：打开预填后的功能页
```

不接受以下方案：

- 把通用编辑和换背景的条件字段全部塞进 `/listing/edit`。
- 为 Chat 单独实现一套换背景或反推业务逻辑。
- 所有需求都强制用户跳转页面。
- 让 LLM 根据松散文本自行拼第三方 API 参数。

## 四、换背景产品体验

### 4.1 页面字段

换背景页面只显示：

1. 商品源图：必填，可上传或选择平台生成结果。
2. 背景来源：
   - 文字描述。
   - 背景参考图。
3. 补充要求：
   - 文字模式使用背景描述。
   - 参考图模式选填，例如“商品放在桌面中央，背景轻微虚化”。
4. 系统识别的输出比例：只读展示。
5. 生成按钮：固定一次一张，并沿用现有费用确认。

页面不显示模型名、质量、分辨率档位或 Provider 参数。

### 4.2 Chat 行为

| 用户输入 | Chat 行为 |
|---|---|
| 一张图＋“换成咖啡店背景” | 直接创建换背景任务 |
| 两张图＋“第一张放进第二张场景” | 第一张商品、第二张背景，直接创建任务 |
| 选中结果图＋上传一张背景图 | 结果图是商品，上传图是背景 |
| “帮我换背景”但没有图片 | 只要求补商品图 |
| 两张图但没有说明角色 | 只询问哪张是商品、哪张是背景 |
| 三张图且角色不明确 | 不猜测，要求明确角色或打开工作台 |
| 用户要求精细检查或主动要页面 | 返回预填操作卡 |

信息完整并且用户明确要求执行时，Chat 必须优先直接调用功能，不能用页面跳转增加步骤。

### 4.3 结果快捷操作

Chat 结果卡和工作台结果卡统一提供：

- 继续编辑：现有二次编辑。
- 换背景：选中当前图片，提示用户描述背景或上传背景图。
- 反推提示词：直接分析当前图片。
- 下载：现有行为。

“更多设置”作为次级入口打开换背景页面。

## 五、换背景接口契约

### 5.1 Endpoint

```http
POST /listing/background-replace
Idempotency-Key: <required>
```

成功返回现有 `ListingSubmissionOut`，后续继续消费现有任务 SSE。

### 5.2 商品源图

上传图：

```json
{
  "kind": "upload",
  "upload_id": "user-ns/image.png"
}
```

平台生成图：

```json
{
  "kind": "generated",
  "image_key": "generated-image-key.png"
}
```

### 5.3 背景来源

文字描述：

```json
{
  "kind": "description",
  "description": "明亮的现代咖啡店，暖色自然光"
}
```

背景参考图：

```json
{
  "kind": "reference",
  "upload_id": "user-ns/background.png",
  "instruction": "商品放在桌面中央，背景轻微虚化"
}
```

### 5.4 完整请求示例

```json
{
  "source": {
    "kind": "upload",
    "upload_id": "user-ns/product.png"
  },
  "background": {
    "kind": "reference",
    "upload_id": "user-ns/background.png",
    "instruction": "商品放在桌面中央，背景轻微虚化"
  }
}
```

### 5.5 校验

- 请求模型 `extra=forbid`。
- `source.kind` 只允许 `upload`、`generated`。
- `background.kind` 只允许 `description`、`reference`。
- 文字模式必须提供非空 `description`。
- 参考图模式必须提供 `upload_id`；`instruction` 选填。
- 不接收 `model`、`n`、`quality`、`size`、`input_fidelity`。
- 上传图和生成图都必须 owner-scoped。
- 不存在与越权统一返回 404。
- Schema 和字段组合错误在入队前失败。

## 六、换背景组装与执行

### 6.1 图片顺序

| 模式 | 输入顺序 |
|---|---|
| 文字背景 | `image[0] = 商品源图` |
| 参考背景 | `image[0] = 商品源图`，`image[1] = 背景参考图` |

第一版不追加链根商品锚点：

- 上述单图和双图正是 APINebula 文档明确展示的形态。
- 减少图片角色混淆和输入 Token。
- 使用 `input_fidelity=high` 和固定保真提示词。
- 如果真实验收不达标，停止上线并重新评审，不能静默增加图片或自动重试。

### 6.2 文字背景提示词

```text
任务：只替换图片 1 的背景。

目标背景：
{description}

必须保持不变：
- 商品主体的形状、比例、颜色、材质和结构
- Logo、包装文字、接口、按钮和细小部件
- 商品在画面中的方向和主体身份

允许调整：
- 为适应新背景而产生的自然阴影、反射和环境光
- 商品与背景接触区域的融合效果

禁止：
- 添加、删除或重绘商品部件
- 修改品牌、文字和包装信息
- 在背景中复制商品
```

### 6.3 参考背景提示词

```text
图片 1 是必须保留的商品源图。
图片 2 只作为目标背景和环境光参考。

将图片 1 的商品放入图片 2 的场景中。
{instruction}

必须保持商品形状、比例、颜色、材质、Logo、包装文字和所有结构细节。
可以根据场景生成自然阴影、反射和环境光，但不得把图片 2 中的物体误认为商品主体。
```

用户文字只能进入对应占位位置，不能覆盖系统保真约束。

### 6.4 比例

- 生成结果作源：继承来源任务比例。
- 上传图作源：读取实际宽高，在现有支持比例中选择最接近的一档。
- 不拉伸商品。
- 页面展示系统选择结果，但第一版不增加比例选择器。
- 尺寸继续通过现有 `generation_size()` 计算。

### 6.5 任务与历史

```text
请求严格校验
  → owner 校验
  → 比例解析
  → 固定提示词组装
  → Listing Job + 1 个 GenerationItem
  → 现有 Redis Queue / Worker
  → 现有 GPT Image Provider
  → APINebula /images/edits
  → 现有存储 / 成本 / SSE / 历史
```

实现要求：

- 新增 `OperationType.REPLACE_BACKGROUND`。
- 不增加数据库表或列。
- 历史中的“换背景”标签从已有 `generation_item.operation_type` 派生。
- 上传源图建立根任务，源图记录为 `product` 角色。
- 背景参考图只记录为 `background` 角色，不参与后续连续编辑的商品锚点解析。
- 生成源图沿用现有父任务和源图关系，保证后续仍可连续编辑。

## 七、反推提示词

### 7.1 Endpoint

```http
POST /image-prompts/reverse
```

上传图：

```json
{
  "source": {
    "kind": "upload",
    "upload_id": "user-ns/image.png"
  }
}
```

平台生成图：

```json
{
  "source": {
    "kind": "generated",
    "image_key": "generated-image-key.png"
  }
}
```

### 7.2 返回结构

```json
{
  "summary": "一张暖色调咖啡店场景中的商品摄影图",
  "subject": "银白色无线耳机充电盒",
  "scene": "现代咖啡店木质桌面",
  "composition": "商品居中偏下，背景虚化",
  "camera": "接近平视的中近景产品摄影",
  "lighting": "左前方柔和自然光",
  "colors": ["暖棕色", "银白色", "米色"],
  "style": "写实商业产品摄影",
  "visible_text": [],
  "constraints": [
    "保持商品比例和金属材质",
    "避免修改 Logo 和接口位置"
  ],
  "uncertainties": [
    "无法仅根据图片确定真实焦段"
  ],
  "prompt_zh": "完整中文提示词",
  "prompt_en": "Complete English prompt"
}
```

### 7.3 实现方式

- 复用现有 Chat 模型的 `base_url`、密钥和模型配置。
- 不新建第二个模型或第二套 Chat Agent。
- 扩展现有 Chat 消息序列化，使应用服务能提交真实图片内容。
- `ReversePromptService` 独立负责加载图片、调用 Chat 模型和校验结果；不把图片分析业务塞入 ChatOrchestrator。
- 使用一个固定结果工具 Schema 约束输出。
- 模型没有返回合法工具参数时直接失败，不从 Markdown 或残缺 JSON 猜测。
- 服务端使用纯格式化函数呈现结果，Chat 模型不能在工具执行后自由改写字段。
- 不声称恢复原作者真实 Prompt；只表述为基于可见画面的重建建议。
- 不持久化到新表。Chat 场景沿用会话文本；页面结果用于展示、复制和带入生成。

## 八、Chat 知识库与工具

### 8.1 工具

| 工具 | 类型 | 费用确认 | 行为 |
|---|---|---:|---|
| `replace_background` | 写工具 | 是 | 创建一张换背景任务 |
| `reverse_prompt` | 读工具 | 否 | 分析指定图片并返回提示词 |
| `open_feature` | UI 工具 | 否 | 返回预填功能操作卡 |

`replace_background` 直接复用正式请求 Schema。Chat 不维护另一套参数模型。

`reverse_prompt` 的工具结果由服务端固定渲染，不再交给 LLM 改写。

`open_feature` 第一版的 `feature` 只允许 `background_replace`。它是本期操作卡的最小协议，不建设通用功能注册表或导航框架；未来增加其他页面时再按实际需求扩展枚举。

### 8.2 操作卡

新增 SSE 事件：

```text
event: action_card
```

```json
{
  "feature": "background_replace",
  "label": "打开换背景工作台",
  "prefill": {
    "source_kind": "upload",
    "source_id": "user-ns/product.png"
  }
}
```

约束：

- 使用 React Router `state` 传预填信息。
- 图片 ID 和提示词不写入 URL。
- 页面只预填，不自动提交或扣费。
- 真正提交时重新 owner 校验。
- 操作卡和费用卡一样是过程态，不增加消息表字段。
- 信息完整时不得用操作卡替代直接执行。

### 8.3 知识库新增内容

```text
换背景
- 支持文字描述背景和背景参考图。
- 必要输入是一张商品图，以及背景描述或背景图。
- 信息完整时 Chat 可直接执行。
- 一次一张、普通分辨率、不支持蒙版。

反推提示词
- 支持上传图片和平台生成图片。
- 输出结构化画面分析、中英文提示词和不确定项。
- Chat 可直接执行。
- 结果是模型重建建议，不是原作者真实 Prompt。
```

## 九、现有知识库真实性审计

本次上线前必须全量审计 `chat_knowledge.md`，不只追加新功能。

### 9.1 已核实为真实

- 商品套图默认 5 张，可配置 3–10 张。
- 套图包含白底、场景、卖点。
- 单图工作台当前固定一张。
- 爆款复刻支持一张产品图和 1–2 张参考图。
- 二次编辑支持微调、重做和连续编辑。
- 卖点文案最多两条、每条最多 12 字。
- 工作台平台选项为淘宝天猫1688、拼多多、京东、抖音电商。
- 4K 仅支持 16:9，并有独立可用性判断。
- 历史、配方查看和首页案例“做同款”存在。
- “记住我”默认开启。
- 密码使用 RSA-OAEP-SHA256 加密传输。
- 视频、可选模板素材库和批量自动改图尚无正式能力。

### 9.2 必须纠正

| 当前描述 | 修正 |
|---|---|
| 普通出图统一支持五种比例 | 说明后端/Chat 支持 4:3，但当前工作台选择器没有 4:3 |
| 所有历史任务都能一键复用 | 仅套图任务支持一键复用；其他任务只能查看配方 |
| 按张扣积分 | 改为按张计入出图额度；具体价格与额度实时查询 |
| 右上角显示“内测免费” | 删除，当前导航已移除此文案 |
| 登录一般不会中途掉线 | 删除不可验证承诺 |
| AI 消除/扩图完全不支持 | 改为暂无专用按钮、画笔、蒙版和正式工作流 |
| 海报、Logo 是独立能力 | 明确它们属于通用自然语言生图，没有专用工作流 |

前端硬编码的 Chat 欢迎语不得继续复制功能清单，改成中性文案：

> 上传图片并告诉我想完成什么即可；你也可以直接问我平台目前支持哪些功能。

### 9.3 后续纪律

- 当前能力必须有代码、接口、验收记录或明确决策作为证据。
- 预告、规划和竞品能力不得写进当前知识库。
- 价格、额度和模型可用性必须调用实时工具。
- 功能上线与下线必须在同一个工作单中同步知识库、工具描述和“不支持”清单。
- 数量、比例、入口等高风险事实增加回归断言，避免知识库与代码再次漂移。
- 保持现有知识库不超过 1500 Token 的约束；用简洁事实替换旧内容，不重复堆叠同义能力描述。

## 十、错误处理

### 10.1 换背景

| 场景 | 处理 |
|---|---|
| Schema 或组合非法 | 422，入队前失败 |
| 图片不存在或越权 | 统一 404 |
| 图片损坏 | 明确失败，不默认 1:1 后继续生成 |
| 队列不可用 | 复用现有准入错误 |
| APINebula 400/422 | 立即失败，不重试 |
| APINebula 401/403 | 配置/权限错误，立即失败 |
| APINebula 429、5xx、连接错误、超时 | 仅按现有网络策略重试或切换 |
| 无有效图片返回 | Provider 错误，任务失败 |
| 商品明显失真 | 不自动重试；由验收或用户重新提交 |

### 10.2 反推提示词

| 场景 | 处理 |
|---|---|
| 无图片 | 页面 422；Chat 追问 |
| 多图未指定 | Chat 询问目标图片 |
| Chat 模型不支持图片输入 | 明确返回功能不可用，不读取文件名猜测 |
| 结构化输出非法 | 请求失败并记录，不猜默认字段 |
| OCR 无法确认 | 写入 `uncertainties` |
| 图片越权 | 统一 404 |
| 网络错误 | 仅网络/I/O 层按现有策略处理，最终失败明确告知 |

## 十一、测试与验收

### 11.1 自动测试

| 层级 | 必测内容 |
|---|---|
| Schema | 两种商品来源、两种背景来源、非法组合、未知字段 |
| 权限 | 上传图、生成图、背景图越权统一 404 |
| Prompt | 保真约束恒在；图片角色和顺序固定 |
| Planner | 一次一个任务；操作类型、比例、尺寸正确 |
| Provider | 文字模式一张图；参考模式两张图；顺序正确 |
| Chat | 直接执行、只追问缺失项、角色不明不猜、操作卡 |
| 反推 | 真实图片进入模型；结构严格校验；中英文提示词完整 |
| SSE/UI | 费用卡、任务进度、结果和快捷操作 |
| 历史 | 结果可回看、下载和继续编辑 |
| 知识库 | 当前能力、限制、入口和暂不支持问答 |

### 11.2 APINebula 与 Chat 模型真实联调

必须覆盖：

1. 一张商品图＋文字背景。
2. 商品图＋背景参考图。
3. 带 Logo 和包装文字的商品。
4. 数码接口、鞋底纹路或美妆泵头等复杂结构。
5. 方图和至少一种非方图。
6. 实际 `b64_json` 返回和尺寸。
7. Chat 模型分析 PNG、JPEG、WebP。
8. 带清晰中文包装文字的 OCR 场景。

### 11.3 换背景人工验收

- 背景按要求替换。
- 商品数量、结构、比例、颜色和材质没有明显改变。
- Logo、包装文字没有明显新增、删除或替换。
- 没有复制商品。
- 没有把背景图物体当成商品。
- 阴影、反射和环境光方向合理。
- 双图角色没有反转。

真实联调达不到商品保真要求时停止上线，重新评审输入图策略；不得用自动重试或隐藏失败掩盖问题。

## 十二、过度设计自检

本方案仅新增两个应用用例和必要的 Chat/UI 接入：

- 一个换背景写用例。
- 一个反推提示词读用例。
- 两个业务工具定义和一个仅支持换背景页面的操作卡工具。
- 一个换背景页面。
- 现有结果卡的两个快捷操作。
- 一次知识库全量纠偏。

明确复用现有：

- 上传服务。
- 用户图片隔离。
- Listing Job。
- Redis 队列与 Worker。
- Provider。
- 成本、费用确认和任务事件。
- 图片存储与历史。
- Chat 模型连接。
- Chat 工具循环和会话记录。

没有为了未来可能出现的功能预建通用工作流引擎、RAG、模板系统、批量框架或新数据模型。

## 十三、完成标准

以下条件全部满足才算完成：

1. 页面和 Chat 均可完成文字换背景与参考图换背景。
2. Chat 信息完整时直接执行，信息不足时只追问缺失项。
3. 反推提示词可从上传图和生成图产生严格结构化结果。
4. 现有二次编辑行为和契约不回归。
5. 不新增队列、Worker、模型或数据库表。
6. 现有知识库完成真实性纠偏。
7. 自动测试通过。
8. APINebula 和 Chat 模型真实联调通过。
9. 五类代表商品的换背景人工验收通过。
10. 未通过商品保真门槛时不发布。
