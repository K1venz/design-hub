# gpt-image-2 中转站对比：诗云 API vs apinebula

- 日期：2026-05-29
- 调研人：Research
- 背景：设计中台图生图主业务需接 gpt-image-2，选型硬约束 = **稳定性 + 价格低 + 发票合规**
- 测试方法：同一冰箱商品图、同任务（图生图加中文促销文案）、同尺寸 1536×1024、medium 质量，两家各实测

## 一、结论速览

| 维度 | 诗云 API | apinebula |
|---|---|---|
| **实测扣费** | 待核控制台（按官方价折算 ≈¥0.44，实扣大概率更低） | **¥0.1/次**（控制台实扣，已确认）✅ |
| 出图质量 | 优秀 | 优秀（与诗云同源 gpt-image-2，肉眼无差） |
| 中文文案渲染 | ✅ 一次成功、零错字 | ✅ 一次成功、零错字 |
| 图生图 /images/edits | ✅ 支持 | ✅ 支持 |
| 返回格式 | b64_json | b64_json |
| 延迟（图生图） | 63–150s | ~90s |
| 协议 | OpenAI 兼容（New API 网关） | OpenAI 兼容（New API 网关） |
| **发票合规** | ✅ 宣称等保三级 + 增值税票 + 审计 | ⚠️ **未确认**，疑号池/逆向网关 |
| 稳定性 | ⚠️ **实测当下整站 502 宕机**（连免费 /v1/models 都挂）+ 曾遇 429「上游负载饱和」 | ⚠️ 撞「分组无渠道 503」，但错误码规范 |

## 二、价格细节

**诗云**：按 token 实计（quota_type=0）。图生图 usage≈ in1054/out1756，按官方价折算 ≈¥0.44/张。
> 注：中转站普遍低倍率补贴，实扣大概率低于此估算 → **待核诗云控制台真实扣费**才能公平对比。

**apinebula**：价格页分两类，但有「分组陷阱」：
| 模型 | 价格页标价 | 所属分组 | 测试 key 能否用 |
|---|---|---|---|
| gpt-image-2 | $0.05/次(固定) | default / image2-business | ❌ key 不在该组，调用报 503 |
| gpt-image-2-vip / -pro | $0.10/次 | vip_image2 | ✅ 能用，**控制台实扣 ¥0.1/次** |

→ 价格页最便宜的 $0.05 版需要对应分组权限，普通 key 够不到；实际可用的是 **¥0.1/次** 的 vip 版。

## 三、风险提示（apinebula）

1. **合规：客服口头称「可以开票」（2026-05-29 用户已问）** ——但票种/主体/品名待钉死。需确认：① 增值税专票还是仅普票；② 开票主体(销售方)是否国内正规公司、能否给全称+税号；③ 票面项目名(技术服务费等)；④ 税点/门槛。**若专票+正规国内主体成立，则合规过关、apinebula 翻盘**；若个人代开/品名含糊/主体海外，则票中看不中用，仍出局。
2. **底层仍疑逆向号池**：分组命名充斥「自建号池」「逆向满血」「CODEX 自建号池」。即便能开"技术服务费"票，底层若是逆向 ChatGPT，业务本身在《生成式AI管理办法》《深度合成规定》下仍属灰色——能开票≠业务合规。
3. **稳定性**：实测撞 503 无渠道；号池类网关稳定性是结构性风险。
4. **结论**：发票门槛已部分扫清，apinebula 从"大概率出局"升为"待定候选"，决胜点 = 开票主体是否正规。

## 三-补、错误码与稳定性实测（2026-05-29，畸形请求探测，不计费）

| 畸形请求 | apinebula(gpt-image-2-vip) | 诗云(gpt-image-2) |
|---|---|---|
| 坏 size 格式 | **400**「不合法的size」 | 502*（宕机污染） |
| 缺 prompt | **422** | 502* |
| 无权限/坏 model | **403** | 502* |
| 分组无渠道 | **503** | — |
| 合法请求 + 免费 /v1/models | 正常 | **502 全挂** |

\* 探测当下**诗云整站 502 宕机**（连免费 /v1/models 都 502），其错误码数据被污染、待恢复补测。

**两点硬结论：**
1. **apinebula 错误码完全是 OpenAI 标准**（400/422/403/503 干净分流），对 failover 错误映射实现最友好；诗云的错误映射风格待其恢复再测。
2. **诗云稳定性露怯**：实测当下整站宕机 + 此前曾 429「上游负载饱和」。它本是"合规首选"，但**可用性已打问号**——更印证主备双中转 failover 的必要性（任一家挂了自动切）。

## 四、给 PM 的建议（据 2026-05-29 实测 + 客服答复修正）

- **apinebula 从"出局"升为"待定候选"**：价低(¥0.1)、出图好、错误码规范、客服称可开票。决胜点收敛到一个 = **开票主体是否正规国内公司 + 能否开增值税专票**。
- **诗云不再是"无脑首选"**：合规资质好(等保三级)，但实测当下整站 502 宕机，可用性打问号；不能把单一供应商当唯一依赖 → **主备 failover 是刚需**。
- **四个待落实动作**（决定最终选型）：
  1. ✅ **已闭环**：apinebula 样票=增值税普通发票，正规公司主体(有名称+税号)，项目名"信息系统增值服务/信息服务费"；用户确认普票够用→合规关通过。
  2. 核诗云控制台：本轮 3 张图真实扣费 —— 才能与 apinebula ¥0.1 公平对比。
  3. 诗云恢复后重测：确认宕机是偶发还是常态 + 补错误映射数据。
  4. 若 apinebula 开票主体正规 → 它与诗云可作主备双中转两家（一便宜一有资质，正好互补）。
- 选型最终影响产品 → 建议在 image-issues 开条目把 owner 指给 PM 跟进。
