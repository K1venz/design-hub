# 三处最小收口设计

日期：2026-08-03  
范围：Chat 知识库真实性、4K 调用超时分类、已交付验收单关账

## 1. 目标

本轮只处理三个已经明确、能够独立收口的问题：

1. 让 Chat 对模型选择入口和模型职责的说明与当前产品一致。
2. 让管理后台按真实渲染档位判断 4K 调用是否超时，不再依赖废弃模型名。
3. 使用聚焦回归和生产只读证据关闭已完成的 ISSUE-0069、ISSUE-0070。

本轮不新增功能入口，不修改 API 契约，不新增数据库字段，不运行付费生图，不扩展为容量或安全验收。

## 2. 现状与根因

### 2.1 Chat 知识库

`config/chat_knowledge.md` 与 `application/chat/system_prompt.py` 仍要求用户回到创作页面选择图片模型，
但当前 Chat 输入框旁已经提供统一下拉，可分别选择文本模型和图片模型。
`tests/test_chat_harness.py` 还把旧话术作为正向断言，导致错误内容受到测试保护。

同时，模型由管理员动态启用和停用。知识库若硬编码当前模型清单，会在管理员修改配置后再次失真。

### 2.2 4K 超时分类

`SqlAlchemyAdminConsoleRepository._effective_call_status()` 通过
`model_call.model == "gpt-image-2-4k"` 识别 4K 调用。当前运行架构已经删除这一虚拟模型 ID，
统一使用稳定模型 ID，并由 `generation_item.render_tier` 区分 `standard` 与 `four_k`。

因此当前 4K 调用无法命中 31 分钟阈值，可能在 6 分钟后被管理后台错误显示为 `uncertain`。

### 2.3 验收单状态

ISSUE-0069 和 ISSUE-0070 的功能已经进入生产，但问题单仍停留在待验证或待复现状态。
问题单缺少当前版本的聚焦回归和生产只读证据，不能只通过修改 frontmatter 关单。

ISSUE-0071 不属于可直接关闭项：生产已经启用持久 RSA 密钥，但
`image-ops/deploy/.env.example` 尚未声明对应配置。该缺口应继续由运维处理。

## 3. 设计决策

### 3.1 Chat 知识库以“行为和入口”为静态事实

知识库描述以下稳定事实：

- Chat 输入框旁的统一模型选择器分别包含文本模型和图片模型。
- 文本模型负责对话与反推提示词。
- 图片模型负责生图、换背景、爆款复刻和二次编辑。
- 其他创作工作台只提供图片模型选择。
- 可用选项以管理员当前启用后由页面展示的模型目录为准。
- Chat 不替用户选择、猜测或自动切换模型。

知识库不再枚举固定模型名单。具体可用模型是运行时数据，页面目录是该信息的事实源。
本轮不增加模型查询工具，也不把动态目录复制进 System Prompt。

`system_prompt.py` 中的工具守则同步改为：本轮使用用户在 Chat 统一选择器中选择的图片模型，
模型不可由 LLM 覆盖。用户无需离开 Chat 页面完成切换。

`test_chat_harness.py` 同时增加正反向契约：新入口和职责必须存在，旧的“回创作页面”话术必须不存在，
固定模型清单不得作为“全部可用模型”的权威声明。

### 3.2 4K 分类关联现有权威字段

管理后台使用相关子查询判断当前调用是否关联 4K 生成项：

```text
model_call.generation_item_id
  -> generation_item.id
  -> generation_item.render_tier == "four_k"
```

有效状态规则保持不变：

| 调用类型 | 仍为 started 后转 uncertain 的阈值 |
|---|---:|
| 4K 图片调用 | 31 分钟 |
| 其他图片调用 | 6 分钟 |
| Chat 调用 | 2 分钟 |

图片生成生产链路在 Worker 创建 `ModelCallContext` 时始终携带 `generation_item_id`，而渲染档位已经固化在
对应 `generation_item` 行中。管理员模型能力测试没有生成项，且只执行普通分辨率能力测试，因此按普通图片阈值处理。

实现使用 SQLAlchemy `EXISTS` 相关子查询，以便概览、汇总、列表和筛选继续复用同一个有效状态表达式。
不新增 `model_call.render_tier`，不回填历史行，也不根据模型名、尺寸或耗时猜测档位。

### 3.3 验收关账以证据为前提

ISSUE-0069 的关闭证据包含：

- 换背景请求、反推提示词和 Chat 工具链聚焦后端测试通过。
- 换背景入口、反推提示词入口及相关结果操作聚焦前端测试通过。
- 生产页面和相关只读接口可访问。
- 沿用问题单中已有真实 APINebula 与真实 Chat 模型测试证据，不重新产生付费调用。

ISSUE-0070 的关闭证据包含：

- 管理员权限、用户管理、图片审核、调用统计和运行日志聚焦后端测试通过。
- 管理后台关键页面聚焦前端测试通过。
- 使用现有管理员身份对生产用户列表、图片列表、模型调用、运行日志和模型目录执行只读烟测。
- 不在生产屏蔽或恢复真实用户图片；写操作闭环由隔离测试数据库验证。

证据通过后，在两张问题单的处理记录中写入版本、命令和结果，状态改为 `已关闭`，owner 改为 `—`。
任一聚焦验证失败时保持原状态，并按事实更新 owner；不得为了完成本轮而忽略失败。

ISSUE-0071 只补充“生产已生效、仓库模板仍缺声明”的事实记录，保持开放并由运维持有。

## 4. 备选方案与取舍

### 方案 A：关联 `generation_item.render_tier`（采用）

优点是使用现有权威字段、无需迁移、适用于所有当前和未来图片模型。改动只进入管理查询层。

### 方案 B：向 `model_call` 增加 `render_tier`

能够让调用记录自包含，但需要数据库迁移、历史数据策略和所有调用入口同步传值。本轮没有其他消费者需要该冗余字段，
因此属于过度设计。

### 方案 C：继续按模型名或尺寸识别

稳定模型 ID 已经不再表达渲染档位；尺寸和耗时也不是可靠业务字段。该方案无法保证准确，明确不采用。

## 5. 错误处理

- 知识库加载行为不变；文件读取失败继续让启动错误传播，不增加默认文案或静默回退。
- 4K 分类查询失败继续作为数据库错误传播，不回落到模型名判断。
- 没有关联生成项的图片调用按其已定义的普通能力测试语义使用 6 分钟阈值。
- 验收命令或生产只读烟测失败即停止关单，保留失败输出的非敏感摘要。
- 验收记录不得写入密码、API Key、Authorization、完整提示词或签名 URL 查询参数。

## 6. 验证范围

### 6.1 后端聚焦验证

- `tests/test_chat_harness.py`
- `tests/test_admin_console.py`
- `tests/test_background_replacement.py`
- `tests/test_reverse_prompt.py`
- 与管理后台审核、运行日志直接相关的现有测试文件
- 对修改的 Python 文件执行 Ruff；执行项目配置的 MyPy 检查

4K 分类新增覆盖：

1. 普通图超过 6 分钟转 `uncertain`。
2. 4K 超过 6 分钟但未满 31 分钟仍为 `started`。
3. 4K 超过 31 分钟转 `uncertain`。
4. Wan 普通图片调用仍使用 6 分钟。
5. Chat 仍使用 2 分钟。

### 6.2 前端聚焦验证

- 统一模型选择器现有测试。
- 换背景与反推提示词入口相关测试。
- 管理后台概览、出图审核和运行日志相关测试。
- 因本轮不修改前端代码，不执行完整前端构建；若聚焦测试暴露类型契约变化，再补 TypeScript 检查。

### 6.3 生产只读烟测

- 确认当前生产前端版本可访问。
- 以管理员身份读取用户、图片、模型调用和运行日志列表。
- 以普通登录用户读取文本和图片模型目录。
- 只记录 HTTP 状态、响应结构和非敏感数量，不输出凭据或完整提示词。
