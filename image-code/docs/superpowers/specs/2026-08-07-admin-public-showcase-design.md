# 管理后台公开出图展示设计

- 日期：2026-08-07
- 范围：管理后台出图审核、`/showcase` 公开接口、`/home` 成果区、`/` 品牌首页走马灯
- 目标：管理员从现有“出图审核”中选择公开展示图片、设置 `/home` 下载按钮，并让两个公开页面共用同一份展示名单

## 1. 现状与问题

当前存在三套彼此独立的数据来源：

1. 管理后台“出图审核”读取 `listing_image`，只支持“正常 / 已屏蔽”合规状态；
2. `/home` 的“看看实朴出的图”读取后端 `SHOWCASE_ENTRIES` 静态清单；
3. `/` 底部走马灯读取前端打包的 12 张静态图片。

因此管理员无法通过后台调整公开展示内容，两个公开页面也无法保持一致。本次改造以 `listing_image` 为唯一公开展示事实源，静态清单和前端静态图片不再参与线上展示选择。

## 2. 产品规则

### 2.1 操作入口

不新增管理后台一级导航。在现有“出图审核”的图片卡片中增加独立的公开展示操作，并增加展示状态筛选。

每张图片同时呈现两个互不替代的维度：

- 审核状态：正常、已屏蔽；
- 展示状态：展示中、未展示；
- 下载设置：允许下载、不提供下载按钮。

管理员可以执行：

- 对“生成成功且审核正常”的图片执行“公开展示”；
- 对“展示中”的图片执行“取消展示”；
- 对公开图片设置 `/home` 是否显示下载按钮；
- 按全部、展示中、未展示筛选图片。

公开展示操作采用确认弹窗，展示该图片关联的用户原始提示词，并说明图片和提示词会同时公开：图片用于 `/home` 成果区与 `/` 品牌首页走马灯，提示词显示在 `/home`。弹窗内提供“允许在 `/home` 下载”开关，默认关闭。

### 2.2 状态约束

- 审核状态与展示状态分别存储，不能用 `normal` 代表公开展示；
- 生成失败、审核已屏蔽的图片不能进入公开展示；
- 用户原始提示词为空的图片不能进入公开展示；
- 图片从正常改为已屏蔽时，必须在同一事务内取消公开展示；
- 图片从已屏蔽恢复正常时，不自动恢复公开展示，必须由管理员重新选择；
- 未公开的图片不能设置为允许下载；取消展示或屏蔽图片时同步关闭下载设置；
- “允许下载”只控制 `/home` 是否提供系统下载按钮，不承诺阻止浏览器另存、开发者工具获取或截图；
- 展示状态与下载设置均未变化时按现有后台行为快速失败，返回冲突错误；
- 取消展示不删除图片、不影响图片所有者的历史记录和正常使用；
- 公开展示只改变公开页面可见性，不改变图片所有权。

### 2.3 排序和空态

- 公开接口按最近设为展示的时间倒序返回；
- 本期不做拖拽排序、置顶、分页面独立名单或复杂内容编排；
- 没有任何展示图片时，`/showcase` 返回空数组；
- `/home` 隐藏整个“看看实朴出的图”区块；
- `/` 保留品牌文字和 CTA，隐藏空的图片走马灯，不使用静态兜底图。

## 3. 数据设计

在 `listing_image` 增加：

- `is_public_showcase: bool`：是否进入公开展示，默认 `false`；
- `showcase_download_allowed: bool`：是否在 `/home` 提供下载按钮，默认 `false`；
- `showcased_at: datetime | null`：最近一次设为展示的时间，用于公开排序；
- `showcased_by: int | null`：执行展示操作的管理员 ID，用于追责和后台详情。

`is_public_showcase=false` 时，`showcase_download_allowed=false`，且 `showcased_at` 和 `showcased_by` 均为空。取消展示或屏蔽图片时同时复位这些字段，确保状态语义唯一。

数据库增加适合公开查询的组合索引，覆盖 `is_public_showcase`、`moderation_status` 和 `showcased_at`。迁移只增加字段和索引；历史图片默认不展示，不把旧静态精选图自动映射为数据库图片。

## 4. 后端架构

### 4.1 管理后台查询与写入

现有管理员图片列表响应增加展示状态和展示操作信息，查询参数增加 `showcase_status`。

新增独立展示状态端点：

`PUT /admin/images/{image_id}/showcase`

请求体包含目标展示状态与下载按钮设置。应用服务负责校验图片成功状态、审核状态、用户原始提示词和状态变化；仓储在同一事务内更新图片并写管理员审计日志。图片已经公开时，可以通过同一端点单独修改下载设置；展示状态和下载设置均未变化时返回冲突错误。

新增审计动作 `image.showcase.update`。审计内容记录图片 ID、前后展示状态和管理员，不写签名 URL、完整提示词或用户敏感输入。

现有屏蔽操作扩展为：若图片正在展示，同一事务内同时关闭展示状态；其审计快照完整反映联动后的状态。恢复操作仍只恢复审核状态。

### 4.2 公开展示查询

`GET /showcase` 从数据库查询同时满足以下条件的图片：

- `listing_image.is_public_showcase = true`；
- `listing_image.moderation_status = normal`；
- `listing_image.status = 成功`。

返回时为图片对象键现签 URL，不在数据库保存临时签名 URL。

公开返回保留现有字段：

- `url`；
- `image_type`；
- `caption`；
- `prompt`；
- `download_allowed`；
- `recipe`。

`caption` 从图片类型和任务品类生成稳定、非敏感的展示说明。`prompt` 直接取关联 `listing_job.prompt`，即用户提交的原始出图要求；不得改用 `generation_item.final_prompt`，后者包含内部组装提示词资产。公开响应不包含用户名或邮箱。`recipe` 从关联 `listing_job` 的品类、比例、图型配比、用户原始提示词和平台配置构造，沿用现有“做同款”能力；不包含内部卡提示词、上传对象或叠字内容。

如果历史数据缺少构造公开配方所需的关键字段，设置“公开展示”时直接拒绝并给管理员明确错误，不返回残缺配方或猜测默认值。

## 5. 前端设计

### 5.1 管理后台

“出图审核”保持现有图片卡片布局，新增：

- 展示状态徽标；
- “公开展示 / 取消展示”按钮；
- “允许下载”设置及状态徽标；
- 展示状态筛选；
- 展示确认弹窗；
- 不满足展示条件时的禁用态和原因提示。

原有屏蔽、恢复操作保留。操作成功后使管理员图片列表和公开展示查询缓存失效，界面读取服务端最终状态。

### 5.2 `/home` 成果区

继续使用 `useShowcase` 和现有详情、做同款交互，只更换后端数据来源。每张卡片必须同时展示图片与用户原始提示词：卡片正文显示两至三行提示词摘要，详情弹窗显示完整原文。

成果区不再把所有图片裁成固定 `4:3`。图片以自身原始宽高比完整展示，卡片高度由图片比例和正文内容自然撑开；响应式列宽随视口变化，不为不同图片强制统一卡片高度。布局采用自适应分栏，避免较短卡片被同一行最高卡片拉伸，同时保持现有移动端单列、宽屏多列的响应式密度。

当 `download_allowed=true` 时，卡片和详情弹窗显示“下载”按钮，并复用系统现有图片下载能力；为 `false` 时两个位置均不渲染下载按钮。此设置仅是产品界面权限，不改变公开预览 URL 的浏览器可访问性。

接口为空或失败时沿用当前策略隐藏整个成果区。

### 5.3 `/` 品牌首页

移除 `HeroPage` 对打包静态图片的依赖，复用 `useShowcase`。走马灯只消费公开接口的 `url`，与 `/home` 使用同一名单和排序。

公开接口加载中时不渲染空图片卡；加载失败时保留品牌文字和 CTA，不显示损坏图片或旧静态兜底内容。

## 6. 错误处理与安全

- 非管理员继续无法访问管理端查询和写入接口；
- 不存在的图片返回 404；
- 无效展示请求、失败图片或缺少配方数据返回 400；
- 重复状态操作返回 409；
- 数据库写入和审计日志必须原子提交，任一失败则整体回滚；
- 公共接口只暴露经筛选的图片信息和可复用配方，不暴露用户身份、审核原因、内部备注、管理员 ID 或对象存储键；
- 公共接口只返回用户原始提示词，不返回内部组装后的最终提示词；
- 公共接口查询再次校验审核和成功状态，即使数据异常也不会公开已屏蔽或失败图片。

## 7. 测试与验收

### 7.1 后端

- 数据库迁移字段、默认值、状态约束和索引；
- 管理员可展示正常成功图片，并写入审计；
- 非管理员不可操作；
- 失败、已屏蔽、提示词为空或缺少关键配方数据的图片不可展示；
- 允许下载只能用于公开图片；
- 公开图片可以独立开启和关闭下载按钮，并写入审计；
- 取消展示清空展示时间、操作人和下载设置；
- 屏蔽展示中图片时自动取消展示，恢复后保持未展示；
- 展示筛选和分页结果正确；
- `/showcase` 只返回展示中、正常、成功图片，按展示时间倒序；
- 公开响应包含对应用户原始提示词和下载设置，但不包含用户身份、审核、对象键和内部最终提示词信息；
- 数据库或审计写入失败时事务整体回滚。

### 7.2 前端

- 管理图片卡正确显示审核和展示两个状态；
- 不符合条件的图片不能触发展示操作；
- 展示、取消展示、下载设置和筛选请求参数正确；
- `/home` 卡片按图片原始宽高比自适应，不再统一裁成 `4:3`；
- `/home` 卡片显示提示词摘要，详情显示完整用户原始提示词；
- `/home` 只为 `download_allowed=true` 的图片显示并执行下载按钮；
- `/home` 渲染公开结果，空或失败时隐藏成果区；
- `/` 使用公开结果渲染走马灯，空或失败时保留正文并隐藏走马灯；
- 两个页面不再引用旧静态展示清单。

### 7.3 构建与回归

- 后端相关测试与完整测试集通过；
- 前端单元测试、类型检查、Lint 和生产构建通过；
- 管理后台、`/home`、`/` 三个页面在桌面和移动尺寸完成浏览器检查；
- 不执行生产图片状态写操作，生产验收只做只读检查；展示写入闭环使用隔离测试数据库验证。

## 8. 明确不在本期范围

- 为 `/home` 和 `/` 配置不同图片名单；
- 拖拽排序、置顶、定时上下线；
- 管理首页文案、Banner 或活动位；
- 自动内容审核、多级审批或申诉流程；
- 阻止用户通过浏览器另存、开发者工具或截图获取公开预览图；
- 迁移或兼容原有静态精选清单。
