# 对话出图沿用上传图片比例设计

## 背景

「帮我设计」对话当前把未指定比例的请求默认成 `1:1`，并把比例视为需要向用户追问的必填项。
用户已经上传产品图时，这会产生不必要的澄清轮，也可能让生成图改变原图比例。

## 目标

- 用户文字明确指定比例时，以文字要求为准。
- 用户文字没有指定比例时，以第一张上传图片的比例为准。
- 无法识别图片比例或比例不受支持时，使用电商兼容性最高的 `1:1`。
- 不再仅因为用户没有输入比例而追问。
- 不改变工作台手动选择比例、爆款复刻和二次编辑的既有行为。

## 已确认规则

1. 只读取本轮第一张上传图片，多图比例不一致时忽略后续图片比例。
2. 支持的业务比例保持现有集合：`1:1`、`3:4`、`9:16`、`16:9`。
3. 允许图片尺寸因整数像素产生轻微误差；宽高比与目标比例的相对误差不超过 1% 时视为匹配。
4. 图片不存在、损坏、格式无法解码、宽高无效或不匹配支持比例时，自动比例为 `1:1`。
5. 自动识别结果只作为“用户未指定比例时的默认值”。用户在自然语言里明确提出比例修改时，文本意图优先。

## 方案

采用后端识别首图比例。

### 比例识别

在 application 层新增独立的图片比例识别单元：

- 输入：图片字节。
- 使用 Pillow 读取尺寸，并按 EXIF 方向校正宽高。
- 将宽高比与四个支持比例比较。
- 在 1% 相对误差内只接受最近的匹配；没有匹配则返回 `1:1`。
- 对预期的图片读取、解码失败返回 `1:1`，不影响对话继续。

该单元不负责存储、对话或出图，只负责从图片内容得到业务比例，便于独立测试。

### 对话数据流

```text
用户消息 + upload_ids
        │
        ├─ 无上传图 ───────────────→ 自动比例 1:1
        │
        └─ 读取第一张上传图
                    │
                    ├─ 匹配支持比例 → 自动比例为识别结果
                    └─ 失败/不支持 ─→ 自动比例 1:1

用户文本 + [系统备注：自动比例]
        │
        ├─ 文本明确指定比例 → 文本比例优先
        └─ 文本未指定比例 ─→ 使用自动比例，不追问
```

`ChatOrchestrator` 在调用文本模型前，通过已有 `UploadService` 加载第一张图片并计算自动比例，
然后把结果加入仅供模型读取的系统备注。备注不写入用户消息正文，也不改变聊天历史的公开展示。

### System prompt

调整出图规则：

- 删除“用户没指定就默认 `1:1`”和“比例不确定必须追问”的旧规则。
- 明确系统备注会给出本轮自动比例。
- 明确用户文字指定比例优先；未指定时必须使用自动比例，不得追问比例。
- 没有图片或识别失败时，系统备注已经给出 `1:1`，模型无需自行兜底。

## 错误处理

- 上传图片读取属于 I/O；图片不存在或读取失败时降级为 `1:1`。
- Pillow 无法识别、图片损坏或尺寸无效时降级为 `1:1`。
- 其他编程错误不捕获，继续遵循项目 fail-fast 规则。
- 现有上传归属校验和出图前校验保持不变。

## 测试

按测试驱动实现：

1. 比例识别：覆盖四种支持比例及整数像素误差。
2. 比例兜底：覆盖不支持比例、损坏图片和无效图片。
3. 对话上下文：第一张图比例被写入系统备注，后续图片不参与决定。
4. 无图或首图读取失败：系统备注使用 `1:1`。
5. System prompt：断言文字明确比例优先、未指定时使用自动比例且不追问。
6. 运行 chat 相关测试、全量后端测试、ruff 和 mypy。

## 非目标

- 不新增任意比例输出能力。
- 不修改底层图像模型支持的尺寸映射。
- 不根据第二张及后续图片投票。
- 不修改工作台手动比例选择和 API 请求模型。
