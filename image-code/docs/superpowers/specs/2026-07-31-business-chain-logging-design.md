# 生产业务链路日志设计

日期：2026-07-31  
状态：待用户复核

## 1. 目标

生产环境只把代码中显式编写的业务链路日志展示到管理后台。日志必须说明：

- 当前属于哪条业务链路；
- 执行到哪个代码方法；
- 该节点正在完成什么业务功能；
- 该节点是正常执行、已处理的业务问题，还是生产/系统问题。

管理员能够从一条日志展开同一 `trace_id` 下的完整链路，并在详情中查看完整提示词。内测阶段不建设长期归档、TOS 归档或独立日志平台。

## 2. 范围与非目标

### 2.1 本期范围

- API 与 Generation Worker 中代码显式写出的 `info`、`warning`、`error` 日志；
- 图片生成、图片编辑、换背景、爆款复刻、对话生图、反推提示词和模型配置测试等关键链路；
- 管理后台「运行日志」列表、筛选、详情和链路时间线；
- 生产日志的结构化字段、脱敏和有界本地存储。

### 2.2 非目标

- 不展示 Uvicorn access、健康检查、SQL、Redis 客户端和第三方依赖的普通日志；
- 不自动记录每个函数的进入和退出；
- 不建设 Loki、ELK、Prometheus 日志检索或分布式追踪平台；
- 不做 14 天保留、TOS 归档或历史审计级留存；
- 不把 API Key、Token、密码、Cookie、签名查询参数写入日志。

## 3. 日志级别契约

### 3.1 `info`

仅表示业务链路节点正常执行。典型事件：

- 请求通过业务校验并创建任务；
- Outbox 事件发布成功；
- Worker 领取任务；
- 模型解析成功；
- 模型调用开始、成功结束；
- 图片保存成功；
- 任务完成；
- 管理员模型连通性测试成功；
- 对话模型完成意图判断或工具调用。

`info` 不用于描述失败、降级或已知异常。

### 3.2 `warning`

表示代码已经识别、能够正常返回或完成收口的业务问题。典型事件：

- 参数、业务状态或幂等冲突；
- 权限不足、账号停用、余额或额度不足；
- 用户选择的模型未启用或已下线；
- 内容审核拒绝、模型明确返回输入不合规；
- 第三方返回明确的业务类 4xx；
- 任务重复投递但已有终态；
- 管理员执行了无效的状态变更。

记录 `warning` 后不得再把同一个问题重复记录为 `error`。

### 3.3 `error`

表示生产任务无法按设计完成的系统或基础设施问题。典型事件：

- 未处理异常或数据不变量被破坏；
- MySQL、Redis、文件存储或对象存储不可用；
- 模型服务网络失败、超时、5xx 或提交结果不确定；
- 图片保存或数据库提交失败；
- Worker lease、slot lease 或任务快照异常；
- 日志文件自身无法写入。

`error` 必须包含安全的异常类型和代码位置摘要，不记录原始密钥或请求头。

## 4. 结构化日志字段

进入管理后台的每条日志必须包含以下字段：

| 字段 | 含义 |
|---|---|
| `event_id` | 单条日志唯一标识 |
| `timestamp` | UTC 时间 |
| `level` | `info`、`warning`、`error` |
| `service` | `api` 或 `worker` |
| `chain` | 稳定的业务链路名称 |
| `event` | 稳定的英文事件名 |
| `action` | 面向管理员的中文功能说明 |
| `logger` | Python 模块名 |
| `function` | `LogRecord.funcName` 自动取得的方法名 |
| `trace_id` | 一次端到端调用的链路标识 |

按场景追加：

- `request_id`
- `job_id`
- `item_id`
- `operation_id`
- `provider`
- `model`
- `status`
- `duration_ms`
- `error_code`
- `error_type`
- `error_summary`
- `prompt`

`logger + function` 是代码位置事实，不手写类名，避免重构后日志名称失真。`chain` 与 `action` 由业务代码显式填写。

## 5. 关键链路节点

### 5.1 图片生成及编辑链路

统一覆盖生成、编辑、换背景和复刻：

1. `SubmissionService`：业务校验通过并创建任务；
2. `OutboxDispatcher`：任务发布到 Redis；
3. `GenerationWorker.process`：Worker 领取任务；
4. `LiveImageExecutorResolver.resolve`：解析用户选择的模型；
5. Provider executor：模型调用开始；
6. Provider executor：模型调用成功、业务拒绝或系统失败；
7. `GenerationWorker._store_and_complete`：保存图片并完成任务；
8. Runtime boundary：未处理异常或任务调度失败。

### 5.2 对话与反推提示词链路

1. 接收用户消息或图片；
2. 加载平台知识与会话上下文；
3. 调用 Chat 模型；
4. 判断回答、引导或生图工具；
5. 创建生图任务或返回提示词；
6. 完成、业务拒绝或系统失败。

### 5.3 管理员模型配置链路

1. 管理员发起连通性测试；
2. 解析 Provider 与模型类型；
3. 执行真实能力测试；
4. 测试成功并签发验证凭据；
5. 保存、启用或设置默认模型；
6. 业务校验失败或外部服务失败。

只在上述影响业务结果的节点写日志，不为普通 getter、DTO 转换、列表查询等方法增加链路日志。

## 6. 日志采集与内测存储

### 6.1 双输出

现有结构化 stdout 保留，供 Docker 与服务器排障使用。新增一个仅接收业务链路日志的 JSONL handler：

- 只有同时包含 `chain` 和 `action` 的 `design_hub.*` 日志才写入后台日志文件；
- API 与 Worker 分别写文件，避免多进程轮转冲突；
- 两个文件位于同一个生产持久卷，管理 API 只读访问。

### 6.2 有界窗口

内测阶段不承诺保存天数，也不上传 TOS。为防止日志耗尽磁盘：

- API 与 Worker 各自最多占用 100 MB；
- 超过上限时滚动并删除最旧文件；
- 这是运行安全上限，不是历史留存策略；
- 日志文件写入失败属于 I/O 故障，业务请求继续执行，同时向 stdout/Sentry 记录一次 `error`。

## 7. 管理后台

新增「运行日志」导航项，仅管理者可访问。

### 7.1 列表

默认按时间倒序显示：

- 时间；
- 级别；
- 服务；
- 链路；
- 方法；
- 功能说明；
- 模型；
- 状态；
- 耗时。

支持按以下条件筛选：

- 级别；
- API / Worker；
- 链路；
- `trace_id`；
- `job_id`；
- 时间范围。

### 7.2 详情与链路展开

点击日志后：

- 显示该条日志全部安全字段；
- 显示完整提示词；
- 按时间顺序加载同一 `trace_id` 的全部链路节点；
- 当前节点高亮；
- `warning` 与 `error` 展示错误码、异常类型和安全位置摘要。

列表接口永不返回 `prompt`；只有管理者访问详情接口时才返回。提示词中的 API Key、Token、密码和签名参数仍经过脱敏。

## 8. API

新增只读管理员接口：

- `GET /admin/runtime-logs`：分页与筛选，不返回完整提示词；
- `GET /admin/runtime-logs/{event_id}`：单条详情；
- `GET /admin/runtime-logs/{event_id}/trace`：同链路时间线。

文件已经滚动删除时，详情返回 404。读取损坏的 JSONL 行属于生产问题，记录 `error` 并使请求失败，不静默跳过。

## 9. 测试与验收

### 9.1 自动化测试

- 只有显式业务日志进入后台日志文件；
- `info`、`warning`、`error` 的代表事件符合级别契约；
- 自动取得正确的模块与方法名；
- API Key、Token、密码、Cookie 和签名参数被脱敏；
- 列表不返回完整提示词，详情返回脱敏后的完整提示词；
- API 与 Worker 文件能够合并排序、筛选和分页；
- 非管理者访问全部返回 403；
- 文件损坏与文件写入失败不会被静默忽略；
- 关键图片生成链路能够通过同一个 `trace_id` 串联。

### 9.2 生产验收

在生产环境执行一次受控任务并确认：

1. 管理后台出现任务创建、入队、Worker 领取、模型调用和完成节点；
2. 每条日志显示真实代码方法与功能说明；
3. 正常节点为 `info`；
4. 受控业务拒绝为 `warning`；
5. 受控基础设施测试环境故障为 `error`；
6. 展开链路可以看到完整提示词但看不到任何凭据；
7. 原有出图、编辑、Chat 和管理员功能不受影响。

## 10. 后续边界

正式开放后如需长期留存，再单独设计 TOS 归档、校验后删除、生命周期规则和审计策略。本期不预埋归档任务或兼容层。
