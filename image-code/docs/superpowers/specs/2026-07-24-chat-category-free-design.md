# Chat 无品类直接出图设计

日期：2026-07-24

## 目标

“帮我设计”不再把用户需求归入任何品类，也不再要求用户从食品、服装、美妆、鞋类、数码中选择。
用户只需上传至少一张图片并说明要做什么，Chat 就直接规划出图并进入费用确认。

Logo、海报、任意商品和其他合法视觉需求均可生成，不因知识库没有列出对应品类而被拒绝。

## 已确认的产品规则

1. Chat 出图没有“确认品类”步骤。
2. Chat 不推断、不记录、不默认任何品类，尤其不得默认 `FOOD`。
3. 开始生成的必要条件只有：
   - 至少上传一张图片；
   - 用户已表达可执行的制作意图。
4. 未指定张数时默认生成 1 张。
5. 未指定比例时沿用第一张上传图片的比例；无法识别时使用 `1:1`。
6. 只有以下情况允许追问：
   - 没有上传图片；
   - 制作意图不明确；
   - 复刻缺少产品图或参考图；
   - 编辑缺少目标图片或编辑指令。
7. 费用确认、安全审核、频控和预算守卫保持不变。

## 架构设计

### 1. Chat 工具契约与 Listing 请求解耦

Chat 使用自己的工具参数模型。`generate` 和 `clone` 的 Chat 参数中不存在 `category` 字段，因此文本
LLM 无法选择、推断或追问品类。

Chat 参数通过明确的应用层转换生成 Listing 命令，品类值为 `None`。这不是新增“通用品类”，而是
表达该请求本身没有品类条件。

现有商品工作台仍可显式提供品类，用于启用已有的专项保真规则；这项能力不暴露给 Chat，也不构成
Chat 的生成前置条件。

### 2. 核心出图支持无品类

Listing 的 `category` 改为可选值且不再默认 `FOOD`。数据库列已经允许 `NULL`，因此不需要数据库迁移。

Prompt 组装从“必须通过品类注册表取得保真块”改为两层：

1. 所有请求都应用与品类无关的基础图片保真规则；
2. 只有结构化工作台显式传入已支持品类时，才额外使用对应专项保真规则。

无品类请求不会写入虚假的品类值，历史记录中的 `category` 保持 `NULL`。

### 3. Chat 决策规则

系统提示和工具描述明确要求：

- 有图片且意图可执行时立即调用生成工具；
- 不得询问、列举或推断品类；
- 不得因为 Logo、海报或知识库未枚举的视觉任务而拒绝；
- 缺图时只提醒先上传至少一张图片；
- 比例和张数使用既定默认规则，不为此追问。

知识库删除固定五品类范围和“自动识别品类暂不支持”的表述，改为说明 Chat 支持基于上传图片完成
全品类视觉生成。

### 4. 新对话能力说明

新建或打开空白 Chat 时，前端展示助手样式的能力卡，但不创建空会话、不写入聊天转录。

能力卡文案：

> 我可以基于你上传的图片，制作任意品类的电商主图、场景图、卖点图、海报和 Logo/品牌视觉，
> 也支持爆款复刻与二次编辑。上传至少 1 张图片，再告诉我想做什么即可。

输入框仍允许先写文字；用户发送时如果没有图片，由 Chat 自然提醒上传。

## 数据流

1. 用户上传 1–3 张图片并描述制作意图。
2. 前端发送文本与 `upload_ids`。
3. Chat LLM 看到不含 `category` 的工具契约。
4. Chat 调用 `generate`，默认 `n=1`，比例按首图自动推导。
5. Orchestrator 将 Chat 参数转换成 `category=None` 的 Listing 请求。
6. Listing 使用基础保真规则组装 Prompt，完成参数校验。
7. 系统展示费用确认卡；用户确认后按原链路生成。

## 错误处理

- 缺少图片：不调用工具，明确提示“请至少上传一张图片”。
- 意图为空或无法执行：只追问具体想做什么，不询问品类。
- LLM 异常传入未知字段：继续使用严格参数校验，返回自然语言提示，但提示中不得出现品类示例。
- 无品类请求进入专项品类注册表属于程序错误，应通过测试和 fail-fast 暴露，不做静默品类回退。

## 测试策略

### 后端

- Chat `generate` / `clone` 工具 schema 不包含 `category`。
- 系统提示不包含固定五品类列表、`category 默认 FOOD` 或 Logo 不支持声明。
- 上传图片并提出 Logo、海报和未枚举商品需求时直接产生费用确认，不出现品类澄清。
- Chat 生成的 Listing 请求 `category is None`。
- 缺图时仍追问上传图片。
- 无品类 Prompt 使用基础保真规则，不注入食品或其他专项品类内容。
- 显式使用品类的结构化 Listing 工作台保持原有专项保真行为。

### 前端

- 新对话和点击“新对话”后展示能力卡。
- 历史会话有消息时不重复展示能力卡。
- 能力卡明确要求至少上传一张图片，且不出现固定品类列表。

### 完整回归

- 后端 Ruff、Mypy、Pytest。
- 前端 ESLint、TypeScript、Vitest、生产构建。

## 非目标

- 本次不增加纯文字生图；仍要求至少一张上传图片。
- 本次不删除结构化商品工作台的专项品类选项。
- 本次不改费用、额度、频控、审核、Provider 或图片比例规则。
- 本次不把“无品类”包装成新的 `GENERAL`、`OTHER` 或任何默认品类。
