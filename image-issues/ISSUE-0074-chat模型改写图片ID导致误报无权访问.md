## 现象

用户在 Chat 中成功上传图片后，预览可以正常显示，但继续要求出图时收到：

> 还差点信息、暂时没法出图：有图片找不到或无权访问，请重新上传后再试。

重新上传图片仍可能得到相同提示。

## 与 ISSUE-0073 的边界

ISSUE-0073 是生成任务已经创建且上游完成，但 Chat 未收到任务终态，导致“出图结果”永久等待。本问题发生在生成任务创建之前：Chat 模型产出的工具参数未能通过图片归属校验，任务根本没有进入队列。

## 生产证据

- 2026-08-07 17:04:14，`POST /uploads` 返回 200。
- 同一图片随后通过 `GET /uploads/{id}` 成功预览并返回 200。
- 会话转录保存的附件 ID 使用当前用户的正确命名空间。
- 2026-08-07 17:04:20，Chat 在写工具参数校验阶段返回“图片找不到或无权访问”。
- `ListingSubmissionService._require_owned_uploads` 只在工具参数中的图片 ID 不属于当前用户命名空间时抛出该错误，因此上传链路和对象存储读取均不是故障点。

## 根因

Chat 将不透明的底层 `upload_id` 注入模型上下文，并要求文本模型在工具调用中原样复述。后端随后直接信任模型返回的 ID。长会话中还会同时注入多轮历史附件 ID，使模型可能改写、截断或选择错误 ID。

图片身份和访问边界属于后端事实，不应由概率模型决定。当前设计把授权相关标识交给模型生成，是本问题的根因；“请重新上传”只是校验失败后的误导性表象。

## 修复边界

- 后端建立当前会话可用图片引用，并负责把模型的图片选择解析为真实 `upload_id`。
- 模型工具参数不再直接承载或决定底层存储 ID。
- 默认出图使用本轮附件；确认或补充指令未带新图时，使用会话中最近一轮带图消息的附件。
- 不允许模型引用当前会话附件集合之外的图片。
- 保持 clone 等多角色图片流程的角色语义，不引入旧参数兼容层。

## 验收条件

1. 本轮上传图片并直接要求出图时，模型无法通过改写 ID 触发误报无权访问。
2. 用户上传图片后先确认方案，再发送“是的”时，后端仍绑定最近一轮有效附件。
3. 长会话存在多轮历史附件时，默认选择最近一轮带图消息，而不是任意历史图片。
4. 非当前会话附件、越权图片和不存在的图片仍被拒绝。
5. 现有 generate、clone、edit、换背景和反推提示词测试保持通过。

## 处理记录

- 2026-08-07 [开发] 完成生产链路取证，确认上传与预览均成功，故障位于 Chat 模型工具参数到后端归属校验之间；与 ISSUE-0073 拆分，开始按后端权威图片绑定方案修复。
