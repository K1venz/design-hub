# 二次编辑 · 编辑模式提示词层草案(ISSUE-0040 · 方案稿,未动代码)

> 起点:PRD §3.12.13 定稿、schema 三列已签上线(parent_job_id/source_image_key/edit_mode{delta,full})、用户早批 delta+full。
> 状态:备稿,待 PM 摘要落地后进三方对。

## 1. 与首次出图的本质差异:源图语义反转

首次出图:参考图 = **真实产品照**,保真块说"保留产品、重绘周围"。
二次编辑:参考图 = **上一次的生成结果**(按 source_image_key 从 TOS 读)——它已含场景/构图/产品,用户要"在此基础上改"。

→ **通用品类保真块在编辑模式下语义冲突**:它的"只重绘产品周围的背景、道具与光线"正是 delta 要锚定不动的东西(或恰是用户要定向改的东西)。
**提案:编辑模式不注入品类保真块,改用自含产品保真语义的「编辑模式块」**(同复刻模式独立成层的先例)。

## 2. 两模式块(第六类卡:编辑模式卡,沿物化块协议)

### delta · 微调(默认)
- **全锚定 + 点改**:构图、场景、光线、产品与一切未点名元素**保持与源图一致**;仅按用户指令做**最小幅度定向调整**。
- 产品本体与包装文字**绝对不变**(自含保真)。
- 命门:①改动外溢(模型把"换背景"做成"重做整张")——锚定句权重最前;②多轮迭代产品漂移(QA D2/TC-05,见 Q1);③用户指令要求改产品本体——锚定块"产品不变"在前压制(产品级改动超出二次编辑 scope)。

### full · 重做
- **产品锚定 + 场景重做**:保留源图中的产品(外形/包装/文字 100% 不变),按用户新要求**重新设计**场景、构图与光线。
- 更接近首次出图,但保真锚 = 源图中的产品。

## 3. 组装序(待 dev 对)

```
[编辑模式块(delta 或 full,自含产品保真)] → [用户编辑指令/新要求] → [modifier 片段(若继承父 job)]
```
- **不拼品类保真块**(§1 冲突;dev compose 编辑分支选编辑块、跳过 CategoryCardRegistry)。
- 编辑指令应必填(与复刻 prompt 选填相反:二次编辑没有指令就没有语义)。
