# 工作台「恢复最近一单」——服务端 + SSE 实时恢复 · 设计稿

- 日期：2026-07-01
- 状态：用户已拍板（B 呈现 + 恢复"当前账号最近一单"；服务端为源 + SSE 接实时）
- 归属：体验优化 A 的一部分（生图流程）。前置：注册/登录轻量打磨（已 demo 认可）。

## 一、背景与问题

用户在工作台一单单跑生图，跳到别的页面再点回工作台时，**上次生图的结果与动画全没了、变成一个空白新任务**。用户要的效果：

> 返回工作台时，看到**当前登录账号最近那一单**生图任务的实时状态——**没出完就显示"生成中"动画，出完就展示结果图**，就像没离开过；不是给我一个新页面。

先前尝试的"内存 store 持久化"只兜住配置、且整页刷新(F5)会丢；不够。

## 二、决策（用户拍板）

1. **数据源 = 服务端**（每单生图本就落 `listing_job`），不靠前端内存记 → 跳转、**整页刷新 F5 都不丢**，且 owner 隔离（只看自己的）。
2. 恢复范围 = **当前账号"最近一单"**（就一单，不是一长列；全量在「历史」页看）。
3. 用 **SSE** 接进行中任务的实时进度；以**历史卡片式**呈现（沿用现有结果区）。

## 三、设计：工作台结果区 = 账号最近一单的实时视图

**数据源（全现成、零新后端端点）：**
- 最近一单：`GET /listing/jobs?limit=1&offset=0` → 取 `[0]`（本人、时间倒序，`useListingJobs`）。
- 详情/状态/已出图：`GET /listing/jobs/{id}`（owner 隔离、404 防枚举，`useListingJob`）。
- 实时：`GET /listing/{id}/events`（SSE，`useListingEvents`）。

**挂载 / 返回工作台时的"恢复"流程：**
1. 取最近一单 job（`limit=1`）。无 → 空态（新账号/从未出图）。
2. 有 → 拉其详情**对账当前状态与已出图**（不依赖 SSE replay，详情是权威快照）：
   - `completed` → 渲染结果图（入场动画）；
   - `failed` / 部分失败 → 渲染失败态（原因可见）；
   - **进行中**（pending/generating）→ 用详情已出的图**预铺槽位** + 订阅该 job 的 SSE → 进度条/shimmer 续播、后续到达逐张点亮。
3. 发起**新的一单** → 它成为新的"最近一单"（generate 返回 job_id 即切到它 + 订阅 SSE），工作台实时显示。

**呈现层复用：** 继续用 `ResultGallery`（结果卡 + motion 入场 + shimmer 骨架 + 进度条 + 失败态 + 「基于此图再编辑」入口）。改的是**驱动数据从"临时 SSE 内存态"换成"账号最近一单（服务端）+ SSE 对账"**。

## 四、状态管理衔接（与已做的内存 store）

- 已做的 `workbench-store`（Zustand）**降级**为只兜**未提交的即时态**：配置项、已上传但还没点生成的预览。这些无服务端记录、靠 store 跳转不丢即可。
- **出图结果不再靠内存 store**——由"账号最近一单（服务端）"驱动，故 F5 也不丢。
- 「新建任务」= 清空即时态（store）+ 结果区回到"最近一单/空态"（不改服务端历史）。

## 五、健壮性 / 边界

- **SSE 断连**（导航卸载/网络抖动，I/O 域）→ 重连；重连后先拉一次详情对账，避免漏帧。
- **订阅已完成的 job**：不依赖后端 replay——步骤 2 的详情对账已给权威终态；SSE 只负责"进行中"的增量。
- **进行中判定以详情 `status` 为准**（不以"有没有 null 槽"猜），防止走开期间已完成却卡在 shimmer。
- **owner 隔离**：详情/事件端点非本人 job → 404，前端 fail-soft 回空态。
- **成本无新增**：恢复只读（jobs/详情/SSE），不触发新出图。

## 六、与「历史」页的关系

- **工作台**：只映射账号**最近一单**的实时状态（活的）。
- **历史页**：全量任务列表 + 详情（不变）。
- 两者同源（`listing_job`），职责区分清晰。

## 七、验收

1. 出图**进行中**跳走 → 回来：进度 + 已出图在、后续继续点亮至完成。
2. **完成后**跳走 / **整页刷新 F5** → 回来：结果图原样在（入场动画重播）。
3. **失败**单 → 回来：失败态 + 原因在。
4. 新账号 / 从未出图 → 空态（不报错）。
5. **owner 隔离**：换账号只看到自己的最近一单；取不到别人的 job。

## 八、落地编排（owner）

- **dev**（image-code）：预计**零新端点**——`jobs?limit=1` + 详情 + SSE 已够。仅需确认 `ListingJobDetail`/`Summary` 暴露的 `status` + `images`（含 url/image_key/失败原因）足以对账；若字段不足再补（涉改动同步 frontend-b、逐字核对；**不新增出图逻辑**）。
- **frontend-b**（image-web）：工作台结果流重构——`WorkbenchPage` 由"临时 SSE 态"改为"账号最近一单驱动 + SSE 对账"；`workbench-store` 降级为即时态；`ResultGallery` 复用。
- **QA**：回归验收 1–5（含 F5 刷新恢复、进行中续播、owner 隔离）。
- **prompt/ops**：本需求不涉提示词；ops 仅最终部署。

## 九、不做（YAGNI）

- 多单"任务 feed"（用户明确要"最近一单"）。
- 新后端"latest"专用端点（`jobs?limit=1` 已够）。
- 跨设备/离线队列。
