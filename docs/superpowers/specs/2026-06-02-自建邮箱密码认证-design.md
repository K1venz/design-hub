# 自建邮箱密码 登录/注册 设计（替换飞书/钉钉 OAuth）

> 状态：已与用户确认设计，待落实施计划（writing-plans）。
> 日期：2026-06-02。作者：前端。跨角色（PM/开发/前端/QA）。
> 关联：替换 ISSUE-0013（OAuth 对接）方向；WP-G（鉴权）后续演进。

---

## 1. 背景与目标

放弃飞书/钉钉 OAuth，改为**自建「邮箱 + 密码」认证**（登录 + 自助注册）。
**复用现有 JWT 签发/校验 + 角色枚举 + 前端守卫**（这层与认证方式无关），只替换"如何获得用户身份"。
遵循本仓铁律 **NO 向后兼容**：OAuth/mock 登录路径**直接移除**，不保留兼容层。

## 2. 范围

**本期做（in scope）**
- 邮箱+密码 **注册**（开放自助）、**登录**。
- 角色：注册默认「设计师」；「管理者」由管理者在**用户管理后台**提升/降级。
- 启动 **seed 管理员**（从 `.env` 读邮箱/密码，不入库不写死）。
- 移除 `/auth/{provider}/callback` + `MockOAuthClient` + `OAuthClient` 端口。

**本期不做（out of scope，YAGNI）**
- 邮箱验证、忘记密码/邮件重置（邮箱字段为以后留口）。
- "记住我"/refresh token（沿用现有 JWT TTL）。
- 第三方 OAuth。

## 3. 决策记录（与用户确认）
- **注册放开度 = A**：开放自助注册，任何人填邮箱/密码即注册即用，默认设计师。
- **身份 = B**：邮箱 + 密码（邮箱唯一标识，便于以后找回）。
- **首个管理者 = C**：启动种管理员账号；**安全形态**——默认邮箱/密码从 `.env` 读（`SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`），不存在则建，建议首登后改密。

## 4. 数据模型（后端新表）

```
app_user
  id            INTEGER PK
  email         VARCHAR  UNIQUE NOT NULL      -- 登录标识
  password_hash VARCHAR  NOT NULL             -- bcrypt
  name          VARCHAR  NOT NULL
  role          VARCHAR  NOT NULL             -- 设计师 | 管理者，默认 设计师
  created_at    DATETIME NOT NULL DEFAULT now
```
> ⚠️ **新建数据库表 + Alembic 迁移**。按"涉及 DB 先问用户"——用户已确认建此表；开发实施时再核连接/迁移。

## 5. 后端设计（image-code，owner=开发）

**复用（不动）**：`PyJwtTokenService`(HS256)、`Role` 枚举、`AuthUser`、`deps.get_current_user`/`require_role`、边界错误映射（401/403/409/400）。

**新增**
- `ports/user_repository.py`：`UserRepository`（get_by_email / get_by_id / add / set_role / list）。
- `infrastructure/db/user_repo.py`：SqlAlchemy 实现 + ORM `AppUser`。
- `infrastructure/auth/password.py`：bcrypt `hash(pw)` / `verify(pw, hash)`（`uv add bcrypt`，CLI）。
- `application/auth/account_service.py`：
  - `register(email, password, name) -> (jwt, AuthUser)`：邮箱已存在→DomainError 409；密码 <8→ValueError 400；存 bcrypt；role=设计师；签 JWT。
  - `login(email, password) -> (jwt, AuthUser)`：查无/密码错→AuthenticationError 401；签 JWT。
  - `seed_admin(email, password)`：不存在则建 role=管理者（启动调用，幂等）。
- `application/admin/user_admin_service.py`：`list_users()`、`set_role(user_id, role)`（不可把自己降级到无管理者？至少保留 1 个管理者——校验"最后一个管理者不可降级"）。

**端点（interface）**
| 方法 | 路径 | 鉴权 | 作用 |
|---|---|---|---|
| POST | `/auth/register` | 公开 | `{email,password,name}` → `{jwt,role,name}` |
| POST | `/auth/login` | 公开 | `{email,password}` → `{jwt,role,name}` |
| GET | `/me` | 登录 | 不变 |
| GET | `/admin/users` | 管理者 | 列用户 `{id,email,name,role,created_at}[]` |
| PUT | `/admin/users/{id}/role` | 管理者 | `{role}` → 改角色 |

> `LoginResponse {jwt,role,name}` 复用现有 schema。`AuthUser.user_id = str(app_user.id)`，`dept=None`（dept 字段在自建认证下恒空，保留以兼容 JWT 载荷；MeResponse 可选加 `email`）。

**移除**：`routes/auth.py` 的 `/auth/{provider}/callback`、`infrastructure/auth/mock_oauth.py`、`ports/auth.py::OAuthClient`、`application/auth/auth_service.py` 的 `role_for_dept`/dept 映射、asgi 中 `AuthService(oauth=...)` 装配 → 换 `AccountService(users=..., tokens=..., passwords=...)`。

**配置**：`Settings` 增 `seed_admin_email` / `seed_admin_password`（SecretStr，默认空=不 seed）。asgi lifespan 启动调 `seed_admin`。

## 6. 前端设计（image-web，owner=前端）

**复用（不动）**：`auth-store`（token persist）、`ProtectedRoute`/`RoleRoute`、`client.ts`（Bearer/401）、`api/auth.ts` 的 `useMe`。

**新增/改造**
- `api/auth.ts`：`useRegister()`（POST /auth/register）、`useLoginPwd()`（POST /auth/login）替换 `useLogin`（OAuth）。
- `pages/LoginPage.tsx` **改造**：移除飞书/钉钉按钮 + 开发 mock 角色切换 → 邮箱/密码表单 + "没有账号？去注册"链接 + 错误内联。
- `pages/RegisterPage.tsx` **新增** `/register`：邮箱/密码/姓名 → 注册成功即写 token → 进工作台（与登录同 store 流程）。
- `api/users.ts` + `pages/AdminUsersPage.tsx` **新增** `/admin/users`（管理者）：用户表 + 角色下拉（设计师/管理者）即时改；`nav.ts` 加「用户管理」(managerOnly)。
- App.tsx：加 `/register`(公开) + `/admin/users`(RoleRoute 管理者)；登录态访问 /register 跳首页。

## 7. 流程

- **注册**：填表 → `POST /auth/register` → 后端建号(设计师)+签 JWT → 前端存 token → `/me` → 工作台。
- **登录**：填表 → `POST /auth/login` → bcrypt 校验 → JWT → 同上。
- **提升角色**：管理者进 `/admin/users` → 改某用户 role=管理者 → `PUT /admin/users/{id}/role` → 该用户**下次登录**拿到新角色（JWT 已签发的旧 token 角色不变，TTL 后失效；可接受）。
- **seed 管理员**：启动若 `SEED_ADMIN_EMAIL` 不存在则建管理者；首登后改密。

## 8. 错误处理（沿用边界映射）
- 注册邮箱重复 → DomainError **409**；密码过弱(<8) → ValueError **400**；邮箱格式非法 → 400（pydantic）。
- 登录邮箱不存在/密码错 → AuthenticationError **401**（统一文案"邮箱或密码错误"，不泄露存在性）。
- 非管理者访问用户管理 → PermissionDenied **403**。
- "最后一个管理者降级" → DomainError 409（保护）。

## 9. 安全
- 密码 **bcrypt** 哈希存储；最小长度 8。
- seed 管理员密码走 `.env`（gitignored），不入库、不写死源码。
- 登录失败统一文案，不区分"邮箱不存在/密码错"。
- JWT 沿用 HS256 + `.env` 密钥 + TTL。

## 10. 测试（image-qa，owner=QA）
- 注册→登录→/me→工作台；重复邮箱 409；弱密码 400；错密码 401。
- seed 管理员登录→/admin/users 列用户→提升某设计师为管理者→该用户重登拿到管理者导航。
- 非管理者访问 /admin/users → 403；最后一个管理者降级 → 409。
