# Chat 边界/知识库/harness 改造 + 商品品类扩展 — 设计稿

- 日期：2026-07-08
- 来源：用户「chat 聊得大胆一些、知识库=平台所有功能且随功能更新同步、harness 优化；增加品类：衣服/美妆/鞋/数码等」
- 状态：coordinator 定稿派单。两条独立线并行：**A 线 chat 改造**（dev+PM）/ **B 线品类扩展**（prompt 卡+dev+frontend-b）。

## A 线：chat 边界 + 知识库 + harness（ISSUE 由 PM 开）

### A1. 边界重定义（「大胆」的精确含义）
现状：`_SYSTEM_PROMPT` 把助手钉死在「收集出图参数」，其他话题一概拒——用户体感拘谨。
新边界（三环）：
1. **核心环（不变）**：出图参数收集→费用确认→出图，卡链/费用闸/频控铁律全不动；
2. **知识环（新增）**：回答**平台任何功能**的怎么用/多少钱/在哪点（依据知识库，不瞎编——知识库没有的功能明说「暂不支持」）；
3. **顾问环（新增=「大胆」）**：电商出图/营销视觉的通用建议（选图型、比例怎么选、卖点文案怎么写更抓人、平台风格差异等），可自然闲聊用户的产品与生意；
- **安全地板（不变松）**：违法违规/涉政涉黄/与平台完全无关的敏感话题仍拒（7.B 内容安全公众全量硬前置不变，现内测+登录墙）。

### A2. 知识库机制（随功能更新同步）
- **单一事实源**：`image-code/src/design_hub/config/chat_knowledge.md`——平台功能地图（每功能：干什么/入口/价格/限制），**≤1500 token 预算**（每条消息注入，控成本）。
- **注入**：orchestrator 组 system prompt 时读入（启动加载、进程内缓存）。
- **同步流程（关键）**：功能上线的 **DoD 增加一项「chat 知识库同步」**——PM 上线记录里勾；QA 验收模板加一条「chat 能正确回答新功能」；内容 PM 起草、dev 落文件（PM 不写 image-code，走 issue 交接或 coordinator 代落）。
- 首版内容：现有全部功能（套图/单图/复刻/编辑/历史/配方复用/帮我设计/价格 ¥0.4/张/内测免费/记住我等）。

### A3. harness 优化（保持方案C零框架）
- system prompt 重构为四段结构：**persona（顾问人设）→ 知识库 → 工具契约 → 守则（安全地板+不编造+费用确认铁律）**；
- 工具 description 打磨（减少占位问句进参数的残余风险）；
- 长会话上下文控制：转录超 N 轮（建议 20）只带最近 N 轮 + 首轮（DB 转录仍全量存，只是 LLM 上下文裁剪）；
- 不引框架、不加新依赖（铁律）。

### A 线验收
① 知识环：问「复刻怎么用/出图多少钱/历史在哪」答案与知识库一致；问知识库外功能（如「能出视频吗」）明说不支持不编造。② 顾问环：问「卖点文案怎么写好」给建设性建议不再拒。③ 核心环零回归（三条真路径+费用闸+0051 持久化）。④ 安全地板：违规话题仍拒。⑤ 长会话 30+ 轮上下文裁剪生效且回答连贯。

## B 线：商品品类扩展（ISSUE 由 PM 开）

### B1. 品类清单（首批 4 个新增 + 现有）
`FOOD 食品`（现有）+ **`FASHION 服装` / `BEAUTY 美妆` / `SHOES 鞋类` / `DIGITAL 数码`**。"等等"后续按需增——注册表制，加品类=加卡+注册，不动架构。

### B2. 卡体系（prompt 权威域；窗口不在线→子 agent 出草案、落地走卡闸纪律）
- 每品类一张品类卡（`image-prompt/category-cards/`）：品类特性块（材质/质感/常见卖点/场景语汇/禁忌——如美妆的肤感与质地、数码的金属质感与参数化卖点、服装的面料垂感与模特/平铺处理、鞋的侧 45° 主角度）；
- 通用产品保真块（产品中性）不动——品类卡是叠加层；
- **卡↔code 逐字核对 pytest 闸照旧**：卡文件与 `CategoryCardRegistry` 硬编码副本必须逐字同步（dev 落常量）。

### B3. 代码与 UI
- **dev**：`CategoryCardRegistry` 注册 4 新品类（常量与卡逐字同步、扩 pytest 卡闸覆盖 9→13 块）；listing 请求 `category` 字段收窄校验放开为 5 值；chat 工具 schema 的 category 同步；openapi 再生。**零建表**（category 本就是请求字段）。
- **frontend-b**：/set 工作台品类选择器（下拉，默认食品）；chat 澄清轮品类问法随 openapi；配方展示/复用带品类（0053 的 recipe.category 已有字段，兼容）。

### B4. 验收（⚠️ 真图部分依赖 key 恢复）
① 5 品类各真出 1 套小图（n=3）看品类特性块生效（美妆有质感/数码有产品感/不再「万物皆花生」）——**¥6 左右，key 恢复后跑**；② 卡闸 pytest 逐字核对绿；③ 前端选择器/chat 品类参数/配方回显带品类；④ FOOD 全链零回归。代码/卡可先落地，真图验收排 key 后。

- **A 线**：PM 起草知识库内容 + 开 issue → dev（知识注入+prompt 重构+上下文裁剪）→ QA A①-⑤（零成本，mock/真豆包澄清轮）→ 部署。
