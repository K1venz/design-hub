## 1. 待对齐项（开工前必须定）

### D2 · 需求单 8 字段 → 引擎 Brief 映射（阻塞 WP-B）<a id="d2"></a>

**问题**：8 字段需求单是**多选**（物料类型多选、尺寸多选、风格多选标签），而引擎 `Brief` 是**单值**（一个 family/品类/子场景/档位/size）。且 **family(模板族)/品类(category)/子场景(subscene)/档位(tier) 不是 PRD 需求单的显式字段**。一张需求单要产出几次出图、每次的 family/品类/子场景/档位从哪来——必须定。

**候选方案（WP-B 开工前选一）**：
- **方案①（推荐）「需求单 + 出图配置分离」**：需求单只存 PRD 8 字段（多选物料/尺寸/风格 + 文案/禁忌/交付）。出图时设计师再开一个「出图配置」选 1 组 (子场景 + 模板族 + 品类 + 档位 + 单个尺寸 + 单个风格)，可对一张需求单发 N 次。映射规则：物料类型→默认子场景候选、风格标签→风格预设候选（设计师确认）。引擎 `Brief` 由「需求单 + 本次出图配置」合成。
- **方案②「需求单直接可出图」**：需求单表单里就强制选单一 family/品类/子场景/档位（把它们加进需求单字段）。简单但偏离 PRD 8 字段定义、且一单只能一种配置。
- **方案③「自动推断」**：物料类型→子场景、风格标签→风格、品类由视觉辅助识别、档位默认标准。最省人工但最易跑偏（与北极星冲突）。

**决策（2026-06-01 用户定）✅ 方案①「需求单 + 出图配置分离」。** 落地映射：

- **需求单（`brief` 表，PRD 8 字段，多选，不含 family/品类/子场景/档位）**：`material_types[]`、`sizes[]`、`styles[]`、`resolution`、`bleed`、`copy_text`、`taboo`、`delivery{}`；客户经 `project.customer_id` 关联。
- **出图配置（`GenerationConfig`，出图时单独提交，不入 brief 表，作 `/projects/{id}/generate` 入参）**：`subscene` + `family` + `category` + `tier` + `size`(单) + `style`(单，从需求单 `styles` 选或自定义) + `n` + `asset_ids[]`(选中的产品/参考图)。
- **合成引擎 Brief** = 需求单(`copy_text`/`taboo`) + 出图配置(`family`/`category`/`subscene`/`tier`/`size`/`style`) + 选中素材(`product_desc`/`reference_images`)。
- **一张需求单可发 N 次出图**（每次一个配置），每个 job 挂 `project_id` + `round_no`。
- **映射建议（前端提示，后端不强制）**：物料类型→默认子场景（主图→S1 / 详情→S3 / 多角度→S4）；需求单 `styles` 标签→出图配置 `style` 候选。后端只校验出图配置字段合法（枚举值、品类有画像、n≤12）。

→ WP-B 据此实现：`brief_to_brief.py` = `合成(brief, GenerationConfig, assets) → 域 Brief`。

### D3 · 项目编号 `project_code`（WP-A 遗留，schema 变更）<a id="d3"></a>

PRD 用 `P{YYYYMMDD}-{NNN}` 人类可读码；当前 `project` 表只有自增 id。**加列 = schema 变更，先问用户**。决策：__待定__（加列 + 迁移 + 生成逻辑约 0.5 人天；不加则用 id）。
