## 〇、入口：两处消费点、一份逻辑

入口动作语义 = **「带着这张图跳进编辑流」**，落点统一为路由跳转：

```
/edit/:jobId/:imageRef        （imageRef = dev Q1 的可寻址 handle，段名随契约定）
```

jobId = 产出该图的 job（即未来的 parent_job_id），imageRef = 该张结果图的稳定 handle。
深链/刷新安全：编辑页自己用 `useListingJob(jobId)` 拉父 job 详情 → 按 handle 定位源图。
owner 隔离免费获得：非本人 jobId → 详情 404 → 复用现行「任务不存在或无权查看」空态（anti-enum 口径一致）。

**入口 ①：历史详情页（HistoryDetailPage）**
- ImageGrid 每张**成功**结果图 hover 动作区，在「下载」旁加「**基于此图再编辑**」按钮 → 跳 `/edit/...`。
- 失败张 / 输入图（产品图、参考图，uploads 桶）**无入口**——可编辑面 = generate 桶成功结果图（用户拍 scope ②），单图 / 套图单张 / 复刻产物 / 编辑产物一视同仁。

**入口 ②：工作台结果区（ResultGallery，三个工作台共用）**
- 现状：`task_completed` 后只 `setJobId(null)`，槽位 url 全来自 SSE，**无 handle**。
- 新增一步（dev #641 已对齐口径「前端将为入口补拉」）：完成时把 jobId 存入 `completedJobId` → `useListingJob(completedJobId)` 补拉详情（复用同一 hook/queryKey，零新端点，每单一次 GET）→ 把 handle 合并进槽位 → 每张成功槽 hover 挂出「基于此图再编辑」。
- **合并规则（不整体重建，保住失败槽）**：失败槽（SSE 原因）原样保留；成功槽按「图型组内序」对位详情里同图型的成功张，取 handle 并刷新为详情新签 url（顺带解决签名 url 过期）。单图流 = 单组同规则。
- 补拉失败（网络）：fail-soft——槽位维持 SSE 态、入口按钮不出现，历史详情入口仍可用，不打断主流程。
- 编辑工作台自己的结果区同样挂入口 → **连续迭代在页内自然闭环**（改完再改，无需绕道历史）。

## 一、编辑工作台（EditWorkbenchPage + EditConfigPanel）

页面骨架与 CloneWorkbenchPage 同构（左配置 / 右单槽画廊，复用 WorkbenchLayout / SSE / newTaskBus / ResultGallery），零新链路：

```
源图（只读 · 不可换）
  [缩略图]  徽标「改自 · 场景图」（继承父张 image_type，仅展示不进组装——Q-γ）
            来源任务 ↗（链到 /history/:jobId）
  （要换一张？回历史或结果区重新选——页内不提供换图，杜绝源图与 parent 链不一致）

编辑方式（两张单选卡，沿复刻档位卡模式）
  ◉ 微调（delta · 默认）   保持这张图的构图与产品不变，只改你说的地方
  ○ 重做（full）           以这张图的产品为基础，按新要求重新设计整个画面，
                           产品与包装文字保持不变
  （卡文案为占位稿，定稿归 prompt——沿 #549 先例，与第六类卡行为逐条对应）

新要求（textarea，必填）
  placeholder · 微调：背景换成厨房木桌 / 光线再暖一点 / 花生再多一点
  placeholder · 重做：全新清晨野餐场景：格子布、竹篮、晨光
  （源图为卖点图时加一行小字：「图上文案暂不支持在编辑中修改」——scope ① 的预期管理，
   文案定稿归 prompt/PM）

生成设置
  比例：delta 档 = 只读 chip「跟随原图 · 3:4」（继承父 job，PRD Q4）
        full  档 = RatioSelect 解锁，预填父值可改
  平台 / 语言：两档均可改（PRD「modifiers 叠新」），预填父 job modifiers
        ——「不动 = 继承」的心智零成本
[ 开始编辑   约 ¥0.40 · 1 张 ]        （scope ③：固定 1 张，无步进器）
```

- 路由不进 WorkbenchRail（入口驱动型页面，无「空白编辑」语义）；rail 无 active 高亮。
- 「新建任务」在编辑页 = 重置表单与结果（源图随路由保留）；要彻底另起 → rail 切换工作台。
- 结果画廊：1 槽，emptyHint「确认源图、写下新要求，点「开始编辑」」，resultLabel「编辑成品」；
  SSE 同 `useListingEvents`，失败槽 / task_failed toast 全沿用。

## 二、迭代链展示（MVP 线性，Q7 方向）

- **历史列表**：SummaryOut 带 `edit_mode`（null=原生单，PM #643 已拍）→ 行内轻徽标「**✎ 微调**」/「**✎ 重做**」。
- **历史详情（编辑单）**：
  - 头部徽标「✎ 微调 / 重做」（edit_mode，与复刻徽标同位同级）；
  - 「**改自这张**」源图回显（DetailOut 签名 url）+ 「查看来源任务 ↗」（parent_job_id → `/history/:parentId`）；
  - 链回溯 = 逐级点 parent（MVP 线性，分叉树视图后置）；
  - 成本行：「本次 ¥0.40 · **迭代链累计 ¥X.XX**」（PRD A.6；累计值需服务端聚合字段，见依赖 #4——前端不做 O(深度) 链拉取）。
- 编辑单详情的结果图同样挂「基于此图再编辑」入口（与入口①同一逻辑）。

## 三、Q-α ~ Q-ζ 逐条表态（PM #643 要求）

| Q | 表态 |
|---|---|
| α 端点形态 | **+1 瘦路由 `POST /listing/edit`**——前端与复刻完全对称：一个 builder（buildEditBody，派生 `Schemas['EditRequest']`）+ 一个 hook，request shape 干净 |
| β 父 prompt 进组装 | prompt 已裁定不带（#645），前端零影响；编辑页 MVP **不展示**父 prompt（避免与「新要求」框混淆，详情页可看），低优后置项 |
| γ 图型卡/overlay | 兑现 scope ①：编辑面板**无 overlay 输入、无图型选择**；父张 image_type 仅作「改自 · X」展示徽标；卖点源加预期管理小字（上文） |
| δ 可编辑源范围 | 兑现 scope ②：入口逻辑一份，覆盖单图/套图单张/复刻产物/编辑产物；失败张前端无入口 + 后端 404 anti-enum 双层 |
| ε 出 1 张 | 兑现 scope ③：CTA 固定「约 ¥0.40 · 1 张」、单槽画廊（同复刻） |
| ζ quality 档 | 前端零影响：CTA 估算 ¥0.40 不变，真实成本沿用 task_completed / 详情 total_cost |
