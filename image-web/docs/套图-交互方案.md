# 套图 · 前端交互方案（需求 #1 第二棒）

> 日期：2026-06-10 · 角色：前端设计师（frontend-b）· 状态：方案待三方对，**不动代码**
> 依据：PRD §3.12.14（PM 56438a5）+ 竞品调研 §1 + QA 套图用例骨架（图型标签契约）
> 提案值沿 PM：MVP 3 图型（白底/场景/卖点）、默认 1/2/2=5 张、总数 3~10、单型可 0、单价 ¥0.40/张

## 〇、单图 / 套图 并存的摆法（PM 拍 (a) 并存后，入口归我提案）

**一个页面、一个分段开关，不拆两个 rail 页**——单图与套图共享 90% 表单（上传/平台/语言/比例/卖点），拆页会复制表单态；分段开关只切「数量节 + CTA + 请求形状」：

```
出图模式   [ 单图 ¥0.40 ｜ 套图 ]      ← segmented control
```
- **单图**：数量节隐藏（固定 1 张，现行 verified n=1 流原样），CTA「开始出图 约 ¥0.40 · 1 张」；结果画廊维持现行不分组。toC 低门槛体验入口（将来免费额度天然配它）。
- **套图**：显示下方 3 行步进器，CTA「一键生成套图」，请求走 plan；画廊按图型分组。
- 默认档位提案 **套图**（页面即「商品套图」、北极星功能优先曝光；单图按钮上明示 ¥0.40 保低门槛可见）——默认档是产品决策，PM/用户可改，前端只换一个初始值。
- 「新建任务」重置回默认档。

## 一、配置栏：「套图结构」步进器（套图模式）

位置：现「生成设置」（平台/语言/比例）之下、「商品卖点 & 要求」之上，新增一节：

```
套图结构                                合计 5 张 · 约 ¥2.00
┌──────────────────────────────────────────────┐
│ 白底图  白底主图，呈现商品细节        [−] 1 [+] │
│ 场景图  生活使用场景展示              [−] 2 [+] │
│ 卖点图  核心卖点与细节特写            [−] 2 [+] │
└──────────────────────────────────────────────┘
```

要点：
- **3 行**（第 4 型「智能补位」随智能匹配进 backlog，不渲染）。每行：图型名 + 一句说明（竞品同款心智）+ `[−] n [+]` 步进器。
- **卖点图行的「图上文案」可选输入**（Q3 收敛，prompt #472 / dev #481 契约 `overlay_texts`）：卖点图数量 ≥1 时该行下方展开一个可选输入——**复用现成 `TagInput` 组件**，限 **2 条、每条 ≤12 字**，placeholder 给示例引导「如：高山七彩花生 / 原生态种植」（PM #476②），输入框下一行辅助文案「不填则输出无文字的卖点特写」（PM #476③，预期管理：系统不代写）。填了 → 随请求带 `overlay_texts: string[]`，卖点图型卡引号 verbatim 锁定（0038 质控）；**不填 → 卖点图不压文字**（纯视觉卖点特写）。数量减回 0 时输入收起、**UI 态保留值但提交时剥离 overlay_texts**（配合后端「overlay_texts 无卖点图 → 400」的显式校验，前端永不发无效组合）。
- 约束逻辑（全部前端实时生效，后端 400 仅兜底）：
  - 单型下限 0：`−` 在 0 时禁用；
  - 总数上限 10：达到 10 时**所有 `+` 禁用**（竞品同款交互）；
  - 总数下限 3：低于 3 不禁用步进器（允许中间状态），但 **CTA 禁用** 并在结构节右上角示数旁提示「至少 3 张」。
- 节标题右侧**实时合计**：`合计 N 张 · 约 ¥(0.40×N)`，与 CTA 同步。
- 配置态结构：`ListingConfig` 的 `n: number` 替换为 `plan: Record<图型, number>`（前端态；请求形状归 dev 契约）。
- 「新建任务」重置回默认 1/2/2。

## 二、CTA 实时计数

```

```
- 文案从「开始出图」改「一键生成套图」；金额/张数随步进器实时变。

## 三、结果画廊：按图型分组

```
商品套图                         ████████░░ 已出 3 / 5 张
─ 白底图 1/1 ───────────────────────────────
  [图]
─ 场景图 1/2 ───────────────────────────────
  [图] [⟳ 出图中]
─ 卖点图 1/2 ───────────────────────────────
  [图] [✕ 失败·重试]
```

要点：
- 画布按请求的 plan 预铺**三个分组段**（数量为 0 的图型不渲染段），每段：图型名 + 段内进度 `done/total` + 缩略网格；占位/淡入/悬停下载沿用现有 ResultGallery 模式。
- 顶部总进度条保留（全套 done/total）；空态 PipelineBeam 不变。
- **SSE 落组规则**：`image_generated` 事件携带**图型标签**（QA 契约①）→ 填**该组**第一个空槽（取代现在的全局到达序填槽）。分批并发下张序可乱、组不会错（QA S8）。
- 下载全部沿用；文件名带图型：`白底-1.png`、`场景-2.png`。

## 四、失败张与重试交互（PM 指派的前端提案）

失败槽位形态（替换占位 spinner）：

```
┌──────────────┐
│  ✕ 生成失败    │   ← 红 tone 哑面，不破坏整组观感
│  (原因摘要…)   │   ← SSE 失败事件的 error 截断一行，hover tooltip 全文
│  [重试 ¥0.40] │   ← 显式标价，点击二次确认不需要（单张小额）
└──────────────┘
```

- job 整体「部分完成」时组段进度显示如 `场景图 1/2（1 失败）`；历史详情页同样标失败张。
- **重试语义（提案，契约归 dev 拍）**：优先 **方案 a：job 内单张重试端点**（如 `POST /listing/jobs/{id}/images/{idx}/retry`）——同 job 同图型同输入重出 1 张、追加 reconcile 计费、历史不碎片化。
- ~~方案 b：前端补发该图型 1 张的迷你套图 job~~——**在 dev 契约（plan 总数 Σ≥3）下不可行**（plan={某型:1} 会 400），且现行 n 流无图型概念也补不出带图型卡的张。**故二选一：方案 a 端点，或 MVP 先不做单张重试**（失败槽只显示原因，known-limits 记一条；部分失败按现行实测是低频事件）。我建议 MVP 可接受「先不做」，a 排后续。

## 五、历史 / 详情适配

- 历史列表卡：副行「1:1 · 5张」扩展为「1:1 · 白1 场2 卖2」（或紧凑徽标），缩略图仍取首图。
- 详情页：候选图网格改为与结果画廊一致的**图型分组段**；每图角标图型徽标；失败张可见（含原因）+ 可重试（若方案 a）。
